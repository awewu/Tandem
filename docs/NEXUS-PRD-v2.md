### ★ 产品 → 营销策划 联动（补齐"营销不完整"）
产品管理不是孤岛，必须结构化输出给下游，否则营销策划断链：
- 4.10 定位/卖点 → **模块2 品牌定位 + 模块3 内容 + 模块7 GEO 内容**(卖点即 GEO 可引用事实)。
- 4.11 应用场景 + 4.3 产品线 → **模块7 战役/营销日历**(按产品线×场景×客群排战役)。
- 4.4 生命周期阶段 → **战役节奏**(新品造势 / 成熟走量 / EOL 清仓)。
- 4.12 竞品对标 → **模块1 洞察 + 模块4 差异化定位**。
- 4.14 技术事实 + 4.7 内容 → **品牌产品页 JSON-LD(源自事实基座) + 模块8 选型**。
- 4.6 价盘 → **模块5 交易 + 促销策略**。
> 验收：任一产品可回答"卖给谁(场景/客群)、凭什么(卖点/技术事实/竞品差异)、什么阶段(生命周期)、走哪条战役/内容/渠道"——形成 **产品→营销 的完整策划链**。下游只读消费不反写；发布投影支持多品牌经销商。

### 产品治理闭环（4.17–4.19）——"能卖 · 会卖 · 合规卖"
- **4.17 定价审批流**：政策提报 → **毛利测算闸(基座3)** → 审批 → 发布 → 审计。无毛利测算/未审批不得生效。
- **4.18 经销商可售目录**：产品/品类按 经销商×等级×区域 授权；越权 SKU 不进选型/报价（供给经销商产品消费）。
- **4.19 产品培训认证**：经销商/销售 按产品线 学习→考核→认证；未认证限制该产品线销售/报价权限（渠道赋能，模块6）。

```
平台层     ── 平台超管：运维·治理面板(系统/门禁/审计/计费)
```

## 模块9.5 · 权限模型：能力 × 范围（不按岗位，按勾选）
> 现实：小团队一人跨职能。**不按固定岗位切角色**，按「**能力(permission) × 范围(scope)**」授权；**岗位 = 可叠加的能力预设包**。一人可持多包。与现有代码一致(`canSeeNavItem(item, permissions, role)` 已 permission 驱动)。
- **能力包(可勾选、可叠加)**：经营视图 · 洞察 · 品牌内容编辑 · 内容发布审批 · GEO运营 · GEO动作审批 · 产品编辑 · 定价提报 · 定价审批 · 渠道管理 · 返利审批 · 平台管理…（细粒度 permission 的分组，对应 nav/API）。
- **范围 scope**：`集团 | 事业部{brand|category, id} | 单品牌 | 单品类`。与能力正交。
- **岗位预设**(仅方便分配，可裁剪)：cmo / bu_gm / product_manager / content_editor / geo_operator / channel_manager / analyst = 若干能力包的命名组合。
- **驾驶舱不绑岗位**：登录后由「持有能力包 × scope」**动态拼**出可见面板与可操作动作。小团队 1 人持多包=看到 CMO 舱+多职能面。
- **治理靠能力闸 + 职责分离(SoD)**：高风险动作绑能力(定价发布=`定价审批`、内容上线=`内容发布审批`、GEO写=`GEO动作审批`)；可选开启"某两能力不得同一人持有"(如 定价提报 ≠ 定价审批)，跨职能也不破基座3/4。

### 9.5-A 权限勾选管理后台（RBAC 后台）　P1
- 账户/预设 × 能力 的**勾选矩阵**(checkbox grid) + 每项授权的 scope 选择器。
- 能力清单(capability catalog)机器可读，一处定义→驱动 nav 可见 + API 鉴权 + 驾驶舱拼装。
- 落 RLS + brand/category 维度切片；变更入审计。现状：`/accounts` 账户管理✅ + permissions[]✅ 已有地基；**能力目录/勾选矩阵/scope/ SoD ❌ 待建**。

## 模块9.6 · Agent 可操作性 + Tandem 分身/搭子调用
### 哪些功能可由 Agent 操作（分级）
每个能力/动作标 `agentMode`：
- **只读/分析 → Agent 自由执行**：洞察、GEO 可见度探测、报表、竞品简报(read-only tool，走 tool-loop)。
- **生成类 → Agent 产 draft，人工发布**：文案/内容/GEO 内容草稿、方案初稿；产出默认 `draft`，上线需 `内容发布审批` 能力(人)。
- **写/高风险 → 受治理动作闸**：定价发布 / 内容上线 / GEO 写动作 / 发返利。复用 `geo-actions` 治理引擎的分区：**green 自动+审计 / yellow 24h 可否决窗口 / red 人工 only**。
- 原则(基座4)：Agent 只能在**事实源+研究支撑+可审计**下动作；无 factRefs 的生成不得对外，无 lift 不得宣称有效。

### Tandem（牛马搭子）分身/搭子如何调用
- **唯一入口 = AI 治理网关**(AGENTS 边界：Nexus 对 Tandem 唯一依赖=AI 治理网关，不扩张到 Tandem 其他板块)。
- Nexus `growth/ai-gateway.service.ts` → `POST {HERMES_CENTER_AI_BASE_URL}/api/ai/governed-chat`(服务令牌鉴权)。见 `contracts/ai/tandem-governed-chat.contract.md`。
- 请求带 `scenario`(growth.copy/growth.geo/diagnosis.consult/crm.sales_coach/competitor.brief) · `actor{userId,role}` · `factRefs`(产品/国标事实) · `bannedTerms`。**由 Tandem 侧决定调用哪个分身(persona)/搭子(companion agent)**——Nexus 不直接碰 Tandem 的 persona/skill 注册表。
- **四闸(Tandem 侧)**：基线闸(场景/角色鉴权) · 合规词闸(广告法) · 事实链闸(factRefs 注入，产出不得回写精算内核) · 输出闸(默认 draft)。每次记 model/tokens/cost + `auditId`。
- **Fail-soft(三级回落)**：`governed-chat` → `hermes-center-ai /api/llm-stream` → 确定性桩；Nexus 本地 `scanCompliance` 始终兜底。
- 现状：`ai-gateway.service` 半成品(llm-stream + 合规兜底 + draft + 成本)✅；**升级指向 governed-chat + 分身/搭子路由 ❌ 待建(跨仓伴随任务)**。

### 9.6-B · 借鉴 Tandem 的「分身 × 搭子工作台」框架（Agent 化架构基线）
> 借鉴 = 抄模式(Nexus 自建)、推理走 governed-chat(不 import Tandem 模块，守边界)。把 GEO 已跑通的"受治理动作+自进化"升级为**平台级分身框架**，其它模块照 GEO 复制。
- **双注册表**(借 Tandem skillRegistry/actionRegistry)：Nexus `skillRegistry`(只读技能：探测/洞察/报表/竞品简报，tool-loop 自由) + `actionRegistry`(写动作：发布/定价/GEO写/返利，经 proposeAction 分区)。geo-actions = actionRegistry 雏形，上抬为平台级。
- **动作分区**(借 proposeAction)：green 自动+审计 / yellow 24h 可否决窗 / red 人工 only。全平台写动作统一此区(不只 GEO)。
- **五个营销分身**(借 persona)：
  - CMO 分身(经营舱)：读=经营诊断/异常归因；写=提案 预算再分配/战役立项。
  - 产品分身/PMM：读=竞品简报/数据完整度体检/上市清单；写=draft 卖点物料、提案 定价政策→**毛利闸(基座3)+定价审批**。
  - 品牌内容分身：读=内容日历/**VI 合规扫描(基座1)**；写=draft 文案内容、提案 发布→**内容发布审批**。
  - GEO 分身(AgenticGEO)：读=探测/缺口/可见度；写=治理 生成→复投→调权重→**lift 验证(基座4)**。最先跑通。
  - 渠道分身：读=经销商健康/sell-through 异常；写=提案 返利/co-op→**返利审批**。
- **S 环反思**(借 company-brain S5)：分身从战役/GEO 结果学习、版本化策略(GEO computeStrategyWeights 已是雏形)。
- **人机边界**(借宪章规则A)：AI 分身**提案**，人**审批**(绑 9.5 SoD + 9.6 agentMode)。
- 架构：`搭子工作台(Nexus UI) → 读技能=本地 skillRegistry / 推理=Tandem governed-chat(分身路由/四闸/审计) / 写动作=本地 actionRegistry(分区→人核准→审计)`。
- 现状：GEO 分身雏形✅(geo-actions+自进化)；**双注册表统一/五分身/搭子工作台 UI ❌ 待建**。
