# PRD：微信公众号草稿箱审核发布 MVP

> 状态：Ready for minimal MVP issue breakdown  
> Triage：`ready-for-agent`  
> 日期：2026-08-01  
> 产品：Rhautt Nexus / 瑞合数智枢纽  
> 实例：Rhautt Comfort / 瑞合瑞德暖通科技集团  
> 供应商：Rysnova / 瑞诺瓦（Powered by Rysnova）

## 1. 背景

Rhautt Nexus 已具备文案生成与编辑能力，但内容生成后仍需运营人员手工复制到微信公众平台，重新处理封面、正文图片和排版，并人工确认应该使用哪个品牌的公众号。该流程耗时、容易选错账号，也无法在平台内保留完整审核记录。

本 MVP 只解决一条核心链路：配置品牌公众号，文案提交单级审核，审核通过后自动同步到微信公众号草稿箱。

微信公众号草稿箱是本期终点。运营人员仍需进入微信公众平台完成最终检查和正式群发，Rhautt Nexus 不直接执行正式群发。

## 2. 已确认需求

1. 前端新增二级目录“发布账号配置”。
2. 公众号必须绑定一个品牌，一个品牌可以绑定多个公众号。
3. 文案提交审核前必须选择品牌及该品牌下的公众号。
4. 文案必须经过平台内单级审核。
5. 未审核通过的文案不得同步至微信公众号草稿箱。
6. 审核通过后，系统自动同步至审核时选定的公众号草稿箱。
7. 系统记录审核结果、同步结果和失败原因。
8. 微信后台正式群发不属于本 MVP。

## 3. MVP 目标

- 跑通“账号配置 -> 文案提交 -> 内容审核 -> 草稿同步 -> 结果查看”的业务闭环。
- 保证审核的是最终待同步内容，审核后不能静默修改。
- 保证品牌与公众号的选择关系正确。
- 保证审核通过后一定存在可追踪的同步任务。
- 避免用户重复操作产生重复审核版本或重复微信草稿。
- 同步失败时给出可理解的原因和明确后续操作。

### 3.1 最小 MVP 业务验证口径

本期只验证一个业务命题：运营人员在 Rhautt Nexus 内选择品牌公众号、提交文案审核，审核通过后，系统能把同一份已审核内容创建到对应微信公众号草稿箱，并在平台内留下可追踪结果。

为保证最小可交付，本期按以下口径收缩：

- 只支持单篇图文草稿，不支持多篇图文组合。
- 只支持标题、摘要、作者、封面图、正文富文本、正文图片和原文链接的基础字段。
- 正文兼容范围限定为段落、标题、加粗、斜体、列表、引用、链接、图片和基础表格；不在白名单内的结构在提交审核前阻止，不做审核后静默转换。
- 审核通过后自动创建同步任务，但同步任务可以由后台扫描器异步执行，不要求页面内即时完成。
- 微信接口在普通测试中使用适配器模拟；上线前必须用一个非生产或测试公众号跑通真实草稿创建。
- 结果不确定时，本期只记录为 `unconfirmed` 并提示人工去微信后台核对，不要求在 MVP 内完成“确认不存在后解锁重试”的完整闭环。
- 明确失败只要求记录脱敏原因和处理建议；自动重试、素材复用优化、死信治理和告警作为后续增强。

issue 拆分前必须确认：

- 审核版本和同步任务统一落在 PostgreSQL，因此审核通过与同步任务创建可以使用同一数据库事务。
- 首批正文内容白名单、图片大小/类型限制和封面图处理方式已经冻结。
- 可用于联调的公众号为新申请公众号；AppID/AppSecret 可获取，IP 白名单可配置，草稿和素材接口权限可验证。

### 3.2 微信公众号联调信息获取

运营或账号管理员在微信公众平台获取和配置：

- AppID：进入 `微信公众平台 -> 设置与开发 -> 基本配置 -> 公众号开发信息` 查看。
- AppSecret：进入 `微信公众平台 -> 设置与开发 -> 基本配置 -> 公众号开发信息` 查看或重置。重置后旧密钥立即失效，需同步更新 Rhautt Nexus 配置。
- IP 白名单：进入 `微信公众平台 -> 设置与开发 -> 基本配置 -> IP 白名单`，添加 Rhautt Nexus 后端服务出口 IP。
- 接口权限：进入 `微信公众平台 -> 设置与开发 -> 接口权限`，确认可获取 access_token，并具备素材管理、草稿箱相关接口能力。
- 联调公众号：优先使用新申请公众号完成首次真实联调；正式运营公众号不用于首次测试。

Rhautt Nexus MVP 的成功终点是“草稿已进入微信公众号草稿箱”。正式群发仍由运营人员在微信公众平台完成。

### 3.3 首批内容白名单

提交审核前，微信渠道稿转换只接受以下内容：

- 标题：必填，长度按微信接口限制校验。
- 摘要：必填，长度按微信接口限制校验。
- 作者：可选，未填时使用系统默认作者。
- 封面图：必填，只接受 JPG/PNG，大小和尺寸按微信接口限制校验。
- 正文图片：只接受 JPG/PNG/GIF，必须可由后端读取，大小按微信接口限制校验。
- 正文 HTML：只允许 `p`、`br`、`h1`、`h2`、`h3`、`strong`、`b`、`em`、`i`、`ul`、`ol`、`li`、`blockquote`、`a`、`img`、`table`、`thead`、`tbody`、`tr`、`th`、`td`。
- 链接：只允许 `http` 和 `https`，不得包含脚本协议。
- 样式：MVP 不承诺保留复杂内联样式；提交预览展示的样式即为审核口径。

不支持的内容包括但不限于视频、音频、小程序卡片、投票、表单、脚本、iframe、外部样式表、复杂交互组件和多篇图文。

## 4. MVP 范围

### 4.1 本期包含

- 手工配置微信公众号 AppID、AppSecret。
- 公众号与品牌绑定。
- 连接测试、启用和停用。
- 当前文案生成/编辑页面接入提交审核。
- 微信渠道稿预览和不可变审核版本。
- 租户内共享待审核池。
- 单级审核通过、退回和作废。
- 审核通过后自动创建草稿同步任务。
- 封面与正文图片上传、正文转换、微信草稿创建。
- 同步成功和明确失败记录；结果不确定仅记录为待人工处理。
- 发布记录和必要审计记录。

### 4.2 本期不包含

- 多级审核、会签、审核 SLA、催办和自动派单。
- 审核任务按品牌、部门或区域分配。
- 提交后由提交人主动撤回；需要修改时由审核员退回。
- 直接正式群发、定时群发和群发人群选择。
- 多篇图文组合草稿。
- 微信草稿双向编辑、自动删除或覆盖旧草稿。
- 结果不确定后的人工确认闭环、解锁重试和重复草稿治理。
- 自动重试、素材复用优化、死信队列治理和告警。
- 微信阅读量、评论和传播数据回流。
- 小程序、视频号、企业微信及其他渠道发布。
- 完整通知中心；MVP 通过页面状态和操作反馈传达结果。
- 微信开放平台第三方授权模式。

## 5. MVP 角色与权限

### 5.1 内容编辑

- 生成、编辑和预览文案。
- 选择品牌和目标公众号。
- 提交审核。
- 查看退回原因并修改后重新提交。
- 查看自己提交内容的审核和同步状态。

### 5.2 内容审核员

- 查看本租户共享待审核池。
- 查看锁定的微信渠道稿和发布目标。
- 审核通过、退回修改或作废。
- 不得审核自己提交的内容。

### 5.3 公众号运营

- 查看同步结果。
- 对失败或结果不确定的任务查看处理建议。
- 对结果不确定的任务到微信后台人工核对，并在 Rhautt Nexus 记录处理备注。
- 在微信公众平台完成最终发布。

### 5.4 账号管理员

- 新增公众号配置。
- 安全录入或重置 AppSecret。
- 测试连接、启用和停用公众号。
- 查看账号异常，但不能读取 AppSecret 明文。

### 5.5 MVP 权限键

- `marketing.wechat_accounts.view`
- `marketing.wechat_accounts.manage`
- `marketing.content.submit_review`
- `marketing.content.review`
- `marketing.content.void`
- `marketing.wechat_drafts.view`
- `marketing.wechat_drafts.note`

前端根据有效权限控制菜单和按钮，后端必须再次校验。所有对象必须执行生产租户隔离。

## 6. 信息架构

在现有内容运营或营销管理一级菜单下提供：

1. `内容创作`：复用现有页面，增加提交审核和状态展示。
2. `内容审核`：本租户共享待审核列表和审核详情。
3. `发布账号配置`：公众号配置、品牌绑定和连接测试。
4. `发布记录`：审核结果、草稿同步状态和失败处理。

不重复创建已有的内容创作入口。

## 7. MVP 核心流程

### 7.1 正常流程

```text
生成或创建文案
  -> 编辑标题、摘要、正文和封面
  -> 选择品牌
  -> 选择该品牌下可用的公众号
  -> 系统生成微信公众号渠道稿并预览
  -> 提交审核并冻结版本
  -> 进入租户共享待审核池
  -> 审核员审核通过
  -> 同一事务内保存审核结果和同步任务
  -> 后台任务上传素材并创建微信草稿
  -> 保存微信草稿标识
  -> 状态变为“已进入公众号草稿箱”
  -> 公众号运营到微信后台正式发布
```

### 7.2 审核退回

```text
待审核
  -> 审核员填写退回原因
  -> 审核退回
  -> 内容编辑修改文案或发布目标
  -> 系统生成新的渠道稿版本
  -> 重新提交审核
```

退回原因必填。旧版本及其审核记录永久保留，新版本不得覆盖旧版本。

### 7.3 同步明确失败

```text
同步中
  -> 微信明确返回失败
  -> 系统分类错误
  -> 记录脱敏失败原因和处理建议
  -> 运营或管理员按建议线下处理
  -> 如需重新同步，由编辑创建新版本并重新审核
```

MVP 不在产品内提供失败任务重试入口。内容错误不得直接修改已审核版本；如需重新同步，必须创建新版本并重新审核。

### 7.4 同步结果不确定

当创建微信草稿的请求超时、连接中断，系统无法确认微信是否已创建草稿时：

```text
同步中
  -> 结果待确认
  -> 禁止直接重试
  -> 公众号运营到微信后台按标题、公众号、版本号和同步时间核对
  -> MVP 内记录人工处理备注，不自动解锁重试
```

人工处理动作必须记录操作者、时间和备注。完整的“确认存在即标记成功 / 确认不存在后解锁重试”闭环作为后续增强，用于避免 MVP 过早引入重复草稿治理复杂度。

## 8. 状态模型

MVP 在数据层分别保存审核状态和同步状态，前端组合展示业务状态。

### 8.1 审核状态

| 状态 | 含义 | 可执行操作 |
| --- | --- | --- |
| `editing` | 编辑中 | 编辑、预览、提交审核 |
| `pending_review` | 待审核 | 审核员通过、退回或作废 |
| `changes_requested` | 审核退回 | 编辑并提交新版本 |
| `approved` | 审核通过 | 只读；等待或查看同步 |
| `voided` | 已作废 | 只读 |

MVP 不支持提交人撤回。提交后如需修改，由审核员退回。

### 8.2 同步状态

| 状态 | 含义 | 可执行操作 |
| --- | --- | --- |
| `not_started` | 未开始 | 等待审核通过 |
| `queued` | 已进入队列 | 查看 |
| `syncing` | 正在同步 | 查看 |
| `succeeded` | 已进入公众号草稿箱 | 查看草稿信息 |
| `failed` | 明确失败 | 查看脱敏失败原因和处理建议 |
| `unconfirmed` | 微信侧结果待确认 | 查看人工处理提示并记录备注 |
| `superseded` | 已被新版本替代 | 只读，禁止重试 |

### 8.3 状态约束

- 同一文案同一时间最多存在一个 `pending_review` 版本。
- 同一审核版本最多存在一个有效同步任务。
- 只有 `approved` 版本可以创建同步任务。
- `failed` 和 `unconfirmed` 在 MVP 内不提供原任务重试；如需再次同步，创建新版本并重新审核。
- 新版本审核通过后，同一文案的旧失败任务进入 `superseded`。
- `unconfirmed` 在 MVP 内不得进入重试队列；后续增强再支持人工核对后解锁。

## 9. 功能需求

### 9.1 发布账号配置

新增公众号必填：

- 公众号显示名称
- 所属品牌
- AppID
- AppSecret

列表展示：

- 公众号名称
- 脱敏 AppID
- 所属品牌
- 启用状态
- 连接状态
- 最近测试时间
- 最近成功同步时间

支持操作：

- 新增
- 更新显示名称或 AppSecret
- 测试连接
- 启用
- 停用
- 查看相关发布记录

MVP 规则：

- 同一租户内 AppID 唯一。
- 一个公众号只绑定一个品牌，一个品牌可以绑定多个公众号。
- 公众号首次连接测试成功后才能启用。
- 公众号被用于审核版本后，品牌和 AppID 不允许修改；如需变更，应停用旧配置并新建配置。
- AppSecret 更新后，系统停止使用旧配置、清除相关访问凭证缓存，并要求重新连接测试。
- AppSecret 只允许录入和重置，前端及查询接口永不返回明文。
- 停用后不能用于新提交，也不能通过仍引用该账号的待审核版本。
- 已进入 `syncing` 的任务不中途强制终止，其最终结果照常记录。

### 9.2 连接测试

连接测试至少确认：

- AppID 和 AppSecret 可获取有效访问凭证。
- 公众号具备本期需要的素材和草稿接口能力。
- 当前服务网络与微信侧 IP 白名单配置允许调用。

连接测试结果分为：

- 正常
- 凭证错误
- 接口权限不足
- IP 白名单错误
- 微信或网络临时异常

页面不得展示 AppSecret、访问凭证、微信完整响应或内部错误堆栈。

### 9.3 提交审核

点击“提交审核”后打开目标确认面板：

- 品牌：必选。
- 公众号：必选，仅展示该品牌下已启用且连接正常的账号。
- 标题：必填。
- 摘要：必填。
- 作者：可选，使用系统默认值兜底。
- 封面图：必填。
- 正文：必填。
- 原文链接：可选。

提交前，前后端必须校验：

- 字段完整且符合微信公众号接口长度和格式要求。
- 正文已完成安全清洗和微信兼容转换。
- 不支持的正文结构必须阻止提交或明确转换，不能留到审核通过后静默删除。
- 封面和正文图片可读取，类型和大小符合要求。
- 品牌与公众号绑定有效，公众号仍为启用状态。
- 当前用户具备提交权限。
- 本租户至少存在一名非提交人的有效审核员。
- 当前文案不存在另一个待审核版本。

校验通过后生成不可变审核版本，保存：

- 原始文案 ID 和版本号。
- 微信渠道稿的标题、摘要、作者、正文和原文链接。
- 封面及正文图片的不可变素材 ID、文件哈希或独立副本。
- 品牌、公众号 ID，以及当时的品牌名、公众号名和脱敏 AppID 快照。
- 提交人和提交时间。
- 渠道稿内容哈希，用于确认审核预览与最终同步内容一致。

重复点击提交不得创建重复审核版本。

### 9.4 内容审核

MVP 使用租户共享待审核池。所有具备审核权限的用户可查看本租户待审核内容，不做品牌分配或指定审核人。

审核详情展示：

- 微信渠道稿移动端预览。
- 标题、摘要、作者、正文、封面和正文图片。
- 品牌和目标公众号。
- 版本号、提交人和提交时间。
- 上一版本审核意见（如有）。
- 公众号当前启用和连接状态。

审核动作：

- 审核通过：可填写意见；确认后不可撤销。
- 退回修改：退回原因必填。
- 作废：作废原因必填。

审核通过前，后端必须再次校验：

- 审核人不是提交人。
- 当前版本仍为 `pending_review`。
- 公众号仍启用并仍绑定审核版本中的品牌。
- 审核版本内容哈希未发生变化。

审核通过时，审核结果与持久化同步任务必须在同一数据库事务中写入。队列消费者从持久化任务表获取工作；即使即时投递失败，也能通过后台扫描继续处理，不允许出现“审核已通过但没有同步任务”的孤立状态。

### 9.5 同步至微信公众号草稿箱

后台任务只读取审核通过的不可变渠道稿：

1. 再次检查公众号启用状态和品牌绑定。
2. 上传前重新计算渠道稿及素材哈希，确认与审核版本一致。
3. 获取并缓存公众号访问凭证。
4. 按审核版本中的不可变素材上传封面和正文图片。
5. 将正文图片替换为微信返回地址，并记录原素材与微信地址的映射；除该地址替换外不得再次改变审核内容。
6. 调用微信草稿创建接口。
7. 保存微信草稿标识、响应时间和素材映射。
8. 更新状态并记录审计事件。

每个审核版本使用唯一同步任务和幂等键。幂等键用于防止平台内部重复消费，但不能假设微信接口会识别该幂等键。

如果微信明确返回成功，状态进入 `succeeded`；明确返回失败时状态进入 `failed` 并保存错误类型；无法确定微信侧结果时进入 `unconfirmed`，禁止自动重试。

### 9.6 失败处理

| 错误类型 | 示例 | MVP 处理 |
| --- | --- | --- |
| 可重试 | 微信临时故障、明确的限流响应 | 状态记为 `failed`，展示原因和“稍后创建新版本重试”的建议 |
| 账号错误 | 密钥无效、权限不足、IP 白名单错误 | 状态记为 `failed`，管理员修复并测试连接；如需再次同步，创建新版本重新审核 |
| 内容错误 | 字段超限、素材格式不支持 | 新建内容版本并重新审核 |
| 结果不确定 | 请求超时、响应中断 | 记录为待人工处理，提示人工核对微信草稿箱，禁止直接重试 |

MVP 不要求复用已经成功上传的素材映射，不提供原任务重试。所有失败和人工处理备注必须留痕。

## 10. 页面交互

### 10.1 内容创作页

- 主操作为“提交审核”，不使用“立即发布”。
- 选择品牌后加载该品牌可用公众号，品牌变化时清空已选公众号。
- 仅有一个可用公众号时可以默认选中，但仍需用户确认。
- 提交前展示冻结后的微信渠道稿预览。
- 提交成功后页面进入只读待审核状态。
- 审核退回后展示原因并恢复编辑能力。

### 10.2 内容审核页

- 默认展示本租户全部待审核内容。
- 支持按品牌、公众号、提交人和提交时间筛选。
- 审核预览必须使用冻结的微信渠道稿。
- 审核通过确认框提示“通过后将自动同步至指定公众号草稿箱”。
- 退回和作废必须填写原因。
- 请求期间禁用重复操作。

### 10.3 发布账号配置页

- AppSecret 使用密码输入，保存后只展示“已配置”和更新时间。
- 连接状态同时使用文字和图标表达。
- 停用和重置密钥需要二次确认。
- 停用时提示受影响的待审核和待同步数量。

### 10.4 发布记录页

展示：

- 文案标题和版本号
- 品牌和公众号
- 提交人和审核人
- 审核状态和同步状态
- 审核时间和同步时间
- 微信草稿标识
- 失败原因和处理建议

操作：

- `failed`：显示失败类型、脱敏原因和处理建议，不显示重试按钮。
- `unconfirmed`：显示“结果待人工核对”，允许记录核对备注，不提供解锁重试操作。

## 11. MVP 数据与约束

### 11.1 微信公众号配置

至少保存：

- 租户 ID、品牌 ID
- 公众号名称、AppID、加密 AppSecret
- 启用状态、连接状态、最近测试时间、最近成功同步时间
- 创建人、更新人和时间戳

约束：同一租户 AppID 唯一。

### 11.2 内容审核版本

至少保存：

- 租户 ID、原文案 ID、版本号
- 冻结的微信渠道稿、审核内容哈希、微信 payload 哈希
- 不可变素材引用及哈希
- 品牌和公众号目标快照
- 提交人、审核人、审核状态、审核意见和时间戳

约束：同一文案最多一个有效待审核版本。

### 11.3 草稿同步任务

至少保存：

- 租户 ID、审核版本 ID、公众号配置 ID
- 唯一幂等键、同步状态、尝试次数
- 微信草稿标识和素材映射
- 错误类型、脱敏错误摘要和内部追踪编号
- 人工处理人、处理时间和备注
- 创建、开始和完成时间

约束：同一审核版本最多一个同步任务。

### 11.4 最小审计记录

记录以下动作的操作者、时间、对象和前后状态：

- 公众号新增、更新密钥、测试连接、启用和停用。
- 文案提交、审核通过、退回和作废。
- 同步开始、成功、失败和结果待人工处理备注。

AppSecret、访问凭证和微信完整响应不得进入普通日志或审计详情。

### 11.5 PostgreSQL 最小表

技术实现可调整字段命名，但 MVP 至少需要以下 PostgreSQL 实体边界：

- `wechat_official_accounts`：公众号配置、品牌绑定、连接状态、密钥密文和启停状态。
- `wechat_content_review_versions`：不可变审核版本、审核状态、审核意见、目标公众号快照和内容哈希。
- `wechat_draft_sync_tasks`：草稿同步任务、同步状态、微信草稿标识、错误摘要和人工处理备注。
- `wechat_publish_audit_events`：账号配置、审核动作、同步动作和人工备注的最小审计事件。

`wechat_content_review_versions` 与 `wechat_draft_sync_tasks` 必须在同一 PostgreSQL 事务中完成“审核通过 + 创建 queued 同步任务”。后台 worker 只消费 `wechat_draft_sync_tasks`，并使用行级锁或等效机制防止并发重复消费。

## 12. 接口与架构约束

- 新接口统一使用 `/api/v2/*`。
- 路由归属登记在 `server/modules/routeOwnership.js`。
- 新业务逻辑放入 `services/api/src/modules/` 对应 NestJS 模块。
- `server-production.js` 不新增内联业务路由，仅允许必要兼容接线。
- 匹配的 NestJS 合同测试通过前，不移除现有 `server/` 兼容能力。
- 账号、审核版本和同步任务均执行后端租户隔离。
- 本 MVP 数据统一落 PostgreSQL，不使用 MongoDB、演示存储或纯内存存储承载生产能力。
- 审核通过与同步任务创建使用同一 PostgreSQL 事务及可恢复任务机制。
- 后台消费者只从 PostgreSQL 同步任务表扫描 `queued` 任务，不依赖内存队列作为唯一事实源。

MVP API 基线：

- `GET /api/v2/marketing/wechat/accounts`：公众号配置列表。
- `POST /api/v2/marketing/wechat/accounts`：新增公众号配置。
- `PATCH /api/v2/marketing/wechat/accounts/:accountId/secret`：更新 AppSecret。
- `PATCH /api/v2/marketing/wechat/accounts/:accountId/status`：启用或停用。
- `POST /api/v2/marketing/wechat/accounts/:accountId/test-connection`：连接测试。
- `GET /api/v2/marketing/wechat/accounts/available?brandId=...`：按品牌查询可提交的公众号。
- `POST /api/v2/marketing/content-review-versions`：创建审核版本。
- `GET /api/v2/marketing/content-review-versions/pending`：待审核列表。
- `GET /api/v2/marketing/content-review-versions/:versionId`：审核详情。
- `POST /api/v2/marketing/content-review-versions/:versionId/approve`：审核通过并创建同步任务。
- `POST /api/v2/marketing/content-review-versions/:versionId/request-changes`：退回修改。
- `POST /api/v2/marketing/content-review-versions/:versionId/void`：作废。
- `GET /api/v2/marketing/wechat/draft-sync-tasks`：发布记录列表。
- `GET /api/v2/marketing/wechat/draft-sync-tasks/:taskId`：发布记录详情。
- `POST /api/v2/marketing/wechat/draft-sync-tasks/:taskId/notes`：为失败或结果不确定任务记录人工处理备注。

DTO 可在技术设计阶段细化，但不得改变以上业务动作、状态语义和权限边界。

## 13. 安全要求

- AppSecret 使用服务端密钥管理或强加密存储，不得明文落库。
- AppSecret 和访问凭证不得返回前端、写入日志或进入埋点。
- 所有接口校验租户、权限和对象归属。
- 正文 HTML 在生成渠道稿时执行白名单清洗。
- 外部图片读取必须限制协议、来源、类型、大小、超时和重定向，防止 SSRF。
- 微信调用设置超时；创建草稿请求超时或响应中断时不得自动重试。
- 前端按钮隐藏不能替代后端权限校验。

## 14. MVP 验收标准

### 14.1 账号配置

- 管理员可以配置公众号并绑定品牌。
- 连接测试成功后才能启用账号。
- 停用账号不能用于新提交或新审核通过。
- AppSecret 保存后无法从页面和查询接口读取明文。
- 已使用账号的品牌和 AppID 不能修改。

### 14.2 提交与审核

- 编辑人员只能选择所选品牌下已启用且连接正常的公众号。
- 提交后生成不可变微信渠道稿和不可变素材快照。
- 审核页面预览内容与同步任务读取内容来自同一版本。
- 同一文案不能同时存在两个待审核版本。
- 提交人不能审核自己的内容。
- 退回原因必填，修改后生成新版本并重新审核。
- 未审核通过的版本不能创建同步任务。

### 14.3 草稿同步

- 审核通过和同步任务在同一事务中保存。
- 即时队列投递失败后，后台扫描仍能继续处理任务。
- 每个审核版本只存在一个同步任务。
- 同步前再次校验账号启用状态和品牌绑定。
- 同步成功后保存微信草稿标识并显示“已进入公众号草稿箱”。
- 明确失败可以按错误类型处理。
- 结果不确定时禁止直接重试，并记录人工处理备注。
- 内容错误创建新版本后，旧任务保持失败或被标记为 `superseded`。

### 14.4 权限与审计

- 无权限用户看不到菜单，直接调用接口也会被后端拒绝。
- 不同租户不能读取或操作彼此的数据。
- 账号配置、审核决定、同步失败和人工处理备注均可追溯。
- 日志、响应和审计记录不包含 AppSecret 或访问凭证明文。

### 14.5 流程终点

- 创建微信公众号草稿成功即完成本 MVP 流程。
- 页面不得把“已进入公众号草稿箱”表述为“已正式发布”。
- 正式发布仍由运营人员在微信公众平台完成。

## 15. MVP 测试范围

必须覆盖：

- 品牌与公众号绑定、启停和连接测试。
- 审核状态流转、禁止自审和退回重提。
- 不可变渠道稿、素材快照和内容哈希校验。
- 审核通过与同步任务原子创建。
- 同步成功、明确失败、内容错误和结果不确定四类路径。
- 重复提交、重复审核和重复消费防护。
- 租户隔离、权限守卫和密钥脱敏。
- 从提交审核到草稿同步成功的端到端测试。

微信接口在普通测试中使用适配器模拟；上线前使用非生产公众号完成一次真实联调。

## 16. MVP 实施顺序

### Phase 1：账号配置

- 发布账号配置页面。
- 品牌绑定、密钥安全存储、连接测试和启停。

### Phase 2：单级审核

- 内容创作页选择品牌和公众号。
- 微信渠道稿生成、预览和不可变版本。
- 共享待审核池、通过、退回和作废。

### Phase 3：草稿同步

- 持久化同步任务和后台消费者。
- 素材上传、草稿创建、错误分类和失败记录。
- 结果待确认记录和人工处理备注。
- 发布记录和审计。

### Phase 4：联调上线

- 使用非生产公众号完成真实联调。
- 验证权限、租户隔离、敏感信息脱敏和端到端流程。
- 通过功能开关先对指定品牌启用。

## 17. 上线前提

- 至少配置一个具备草稿接口能力的非生产或测试公众号。
- 微信侧 IP 白名单配置完成。
- 生产 AppSecret 加密存储方案可用。
- 租户内至少有一名内容编辑、一名不同用户的审核员和一名公众号运营。
- 已验证标题、摘要、封面、正文图片及富文本的真实同步效果。
- 已跑通成功、退回、明确失败和结果待确认四条验收路径。
