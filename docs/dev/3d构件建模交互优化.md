# 3D 构件建模交互优化 PRD

## Problem Statement

当前 `4003/viewer` 已经具备统一 3D 工作台、构件库、手工构件 CRUD、IFC/GLB 打开、模型生成和 BOM/报价联动的基础能力，但实际建模体验仍然不像专业设计软件：

1. 3D 视图中容易选中外层黄色/透明边界框、辅助框或场景参考对象，导致用户难以准确选中真实构件。
2. 构件库仍偏普通列表，缺少类似标准设计软件的工具栏、分类、构件卡片和参数预设体验。
3. 构件放置前和放置后都缺少清晰的参数编辑入口，用户不能顺畅地调整长宽高、厚度、管径、开启方向、安装高度等属性。
4. 门、窗、设备等导入或新建构件不能方便旋转，无法满足手工建模和布置需求。
5. 3D 视图、构件库、属性面板和对象列表中缺少稳定中文标识，用户看到的经常是 UUID、英文类型或技术字段。
6. 右侧“模型来源”区域偏技术调试信息，占用建模属性空间，不符合用户对模型对象管理的理解。

用户期望 `4003/viewer` 从“能生成和保存模型”进一步升级为“可手工建模和编辑的 3D 设计器”：左边选工具和构件，中间拖拽建模，右边看对象树和属性，所有真实构件都能被准确选择、移动、旋转、改尺寸、删除和保存。

## Solution

在不改变 IFC/GLB 原生导入和查看能力的前提下，优化 `4003/viewer` 的 3D 构件建模交互：

1. 建立明确的 3D 可选对象边界：真实构件可选，辅助框、场景边界、参考网格、相机辅助线默认不可选或锁定。
2. 将左侧构件库升级为设计软件式工具面板：竖向工具栏、顶部分类页签、构件卡片、中文名称、默认参数和可编辑预设。
3. 支持构件放置前参数预设和放置后属性编辑，统一保存到后端持久化结构。
4. 支持门、窗、墙体、设备、管线等构件的旋转能力，并把旋转值写入组件实例数据。
5. 在 3D 视图、构件库、属性面板、对象树中统一显示中文业务名称。
6. 移除或重构右侧“模型来源”卡片，将其升级为类似 Photoshop 图层面板的模型对象树。
7. 保持 IFC/GLB 导入模型的原生能力可用：不重写、不降级、不破坏当前模型加载、查看、缩放、旋转、选择边界和错误处理。

## Product Goals

1. 用户能稳定选中真实构件，而不是误选场景外框或辅助对象。
2. 构件库呈现方式接近专业设计软件，支持快速切换构件分类和工具。
3. 用户能在放置前选择构件默认参数，放置后继续修改尺寸、位置、旋转和业务属性。
4. 门、窗、设备等构件支持旋转，旋转结果可保存并在刷新后恢复。
5. 所有用户可见的构件名称、分类、属性和对象树节点都使用中文显示。
6. 右侧面板从“模型来源调试信息”升级为“对象树 + 属性编辑”的工作区。
7. 原有 IFC/GLB 导入和查看能力保持可用，不能因为本次交互优化而退化。

## Non-Goals

1. 不重写 IFC/GLB 加载器，不替换现有 BIM Viewer 原生能力。
2. 不改变 IFC/GLB 文件格式解析策略，不新增复杂 BIM 属性抽取作为本 PRD 的必须范围。
3. 不做完整 CAD 级布尔编辑、门窗自动开洞、碰撞求解或参数化族系统。
4. 不把 `4001/designer.html` 或 `4001/rysnova-bim-designer.html` 重新作为正式产品页面。
5. 不引入 iframe 或第二套 3D 页面来解决体验问题。
6. 不把构件数据只保存到 React state、localStorage 或 Three.js 临时对象中。

## Hard Constraints

1. `4003/viewer` 仍然是唯一正式 3D 工作台页面。
2. IFC/GLB 导入模型能力属于既有原生能力，本次不得破坏：
   - 本地 IFC 文件打开能力必须继续可用。
   - GLB 文件打开能力必须继续可用。
   - 后端 artifact/model source 打开能力必须继续可用。
   - 模型查看、缩放、旋转、平移、fit view 和加载错误提示不得退化。
3. 对 IFC/GLB 的改动只能是外围 UI 集成、对象树展示或选择状态适配；不得为了手工构件 CRUD 重写加载器主逻辑。
4. 辅助框、边界框、网格、坐标轴、相机辅助线、光照辅助线、场景容器默认不得作为普通业务构件被选中。
5. 所有用户可见文本必须是中文业务文案，字体栈必须包含中文字体，例如 `PingFang SC`、`Microsoft YaHei`、`Noto Sans CJK SC`、`Source Han Sans SC` 和 `sans-serif` fallback。
6. 构件实例的尺寸、位置、旋转、名称、类型、系统归属、BOM 映射和删除状态必须通过后端 API 持久化。
7. 新增生产业务 API 必须落在 `/api/v2/*` 方向和 `services/api/src/modules/rysnova-bim` 等目标架构模块中。
8. 不得继续把新业务逻辑堆进旧静态 HTML 或 `server-production.js`。

## Users

1. 设计师：从构件库拖拽墙体、门窗、设备和管线，手工搭建或调整 3D 模型。
2. 技术支持工程师：打开 IFC/GLB 或生成模型，准确选择构件并检查对象属性。
3. 方案顾问：查看模型中的设备、管线、BOM 和报价摘要，确认手工修改是否进入商业结果。
4. 项目管理人员：通过对象树理解当前模型结构、构件状态、隐藏/锁定状态和模型来源。

## User Stories

1. As a designer, I want auxiliary scene boxes to be unselectable by default, so that I can click real walls, doors, equipment and pipes accurately.
2. As a designer, I want the left panel to look like a design tool palette, so that I can switch between layout, equipment, pipe, annotation and edit tools quickly.
3. As a designer, I want component cards to show Chinese names and default dimensions, so that I know exactly what I am placing.
4. As a designer, I want to set wall thickness, wall height and default length before placing a wall, so that repeated placement is efficient.
5. As a designer, I want to set door width, height, thickness and opening direction before placing a door, so that the model matches the room layout.
6. As a designer, I want to rotate a selected door or window, so that I can align it with the wall direction.
7. As a designer, I want to rotate equipment after placement, so that installation direction and pipe connection direction are clear.
8. As a designer, I want the selected component property editor to show type-specific size fields, so that I do not edit irrelevant fields.
9. As a designer, I want rotation, size and position changes to update the 3D object immediately, so that modeling feedback is visual.
10. As a designer, I want all edits to be saved and restored after refresh, so that my modeling work is not lost.
11. As a technical support engineer, I want imported IFC/GLB models to keep their original opening and viewing behavior, so that review workflows remain stable.
12. As a technical support engineer, I want IFC/GLB models to appear in the object tree without breaking the loader, so that imported models can be managed visually.
13. As a project user, I want the right panel to show a tree of model objects, so that I can find generated components, manual components and imported models.
14. As a project user, I want object tree nodes to support visibility and lock state, so that I can avoid editing the wrong layer.
15. As a sales user, I want manually edited equipment and pipes to continue feeding BOM and quote summaries, so that commercial outputs reflect the design.

## Functional Requirements

### Selection and Interaction

1. Real business components must be selectable: wall, door, window, room/zone, equipment, pipe-route, duct-route and generated HVAC components.
2. Scene helpers must not be selected by normal click: bounding boxes, reference grids, axes, camera helpers, light helpers, outline helpers and container meshes.
3. Selection hit testing must prefer the nearest visible selectable business component.
4. Locked objects must not be editable or draggable.
5. Hidden objects must not be selectable from the viewport, but may remain visible in the object tree.
6. Clicking empty space should clear selection only when no selectable object is hit.
7. Existing orbit, pan, zoom and fit-view behavior must remain usable.
8. Default camera must not auto-rotate.
9. Camera must not reset after left-button or right-button drag ends.

### Component Library

1. The left panel must include a vertical tool rail with icon/text fallback labels.
2. The component library must include category tabs or segmented controls, at minimum:
   - 布局
   - 设备
   - 管路
   - 标注
   - 编辑
3. Layout components must include at minimum:
   - 墙体 240mm
   - 门 900mm
   - 窗 1500mm
   - 房间标注
4. Equipment components must include heat pump, boiler, FCU, radiator, underfloor heating zone, AHU/fresh-air unit, vent, thermostat and manifold where current catalog data exists.
5. Pipe components must include refrigerant pipe, air duct, underfloor loop and condensate pipe where current catalog data exists.
6. Component cards must show Chinese display name, short parameter summary and placement hint.
7. Component cards must expose editable default parameters before placement.
8. The component library must remain keyboard and mouse usable; no tiny click-only UI for critical modeling actions.

### Property Editing

1. Selected component editor must show Chinese labels and type-specific fields.
2. Common fields:
   - 名称
   - 类型
   - 系统
   - 楼层
   - 标高
   - X/Y/Z 位置
   - 旋转角度
   - 状态
3. Wall fields:
   - 长度
   - 厚度
   - 高度
   - 起点
   - 终点
   - 墙体类型
4. Door/window fields:
   - 宽度
   - 高度
   - 厚度
   - 离地高度
   - 开启方向
   - 所属墙体
5. Equipment fields:
   - 长度
   - 宽度
   - 高度
   - 容量
   - 型号/SKU
   - 安装方式
   - 所属系统
   - 接口方向
6. Pipe/duct fields:
   - 管径
   - 宽度
   - 高度
   - 路径点
   - 长度估算
   - 材质
   - 保温信息
   - 所属系统
7. Editing any numeric geometry value must immediately update the 3D representation.
8. Invalid values must be rejected with Chinese validation messages.

### Rotation

1. Door, window, equipment, wall and route components must support persisted rotation.
2. Rotation can be edited through numeric input in the property panel.
3. Rotation can also be exposed through viewport interaction if a lightweight rotate handle already fits the existing implementation.
4. Rotation must be stored in the component instance contract.
5. Rotation must be restored after refresh/reopen.
6. Rotation must not mutate IFC/GLB imported model geometry unless the imported model source itself is explicitly selected for transform editing in a later approved scope.

### Object Tree / Layer Panel

1. The right panel must remove or demote the current “模型来源” debug-style card.
2. The right panel must provide a model object tree or layer-style panel.
3. The object tree must group objects at minimum by:
   - 当前项目
   - 生成模型
   - 手工构件
   - 墙体
   - 门窗
   - 房间/区域
   - 设备
   - 管线
   - IFC/GLB 导入模型
4. Each tree node must display a Chinese name.
5. Tree nodes should show visibility, lock and selected states.
6. Selecting a tree node should select/highlight the corresponding model object where applicable.
7. Imported IFC/GLB sources may appear as source nodes with child metadata only when available; lack of deep BIM decomposition must not block the panel.
8. The object tree must not replace existing IFC/GLB loading behavior.

### Chinese Display

1. Component names must use Chinese business names by default.
2. Internal IDs may be shown only as secondary debug text or collapsible metadata.
3. UUID must not be the primary label for user-facing model objects.
4. Empty states, validation errors, loading states and placement hints must be Chinese.
5. No mojibake, missing glyph boxes or English placeholder labels are acceptable in the final UI.

### Persistence and Data Contract

1. Component default template values can originate from seed data or backend catalog data.
2. Placed component instances must persist:
   - component ID
   - template ID
   - Chinese display name
   - category
   - type
   - dimensions
   - position
   - rotation
   - elevation
   - visibility
   - lock state
   - system key
   - business metadata
   - BOM metadata
   - status
   - version
3. Object tree state that affects modeling behavior, such as hidden or locked objects, must be persisted when it changes the saved design state.
4. View-only UI expansion/collapse state may remain client-local unless product later requires cross-device persistence.
5. All persistence must use authenticated backend API paths and tenant-scoped storage.

## Implementation Decisions

1. Keep `4003/viewer` and the existing React/Next.js page as the implementation root.
2. Keep existing generated HVAC, manual component CRUD and model source persistence contracts as the base.
3. Add a selectable-object policy around Three.js scene objects instead of treating every mesh as a business component.
4. Mark scene helpers and imported source containers with non-selectable metadata.
5. Add or extend component instance fields for Chinese display name, visibility, lock state and rotation when current contract is insufficient.
6. Convert the component library UI into a tool-palette style interaction without embedding or reviving old static HTML.
7. Keep IFC/GLB loader code stable; only adapt source metadata and object tree presentation around it.
8. Treat imported IFC/GLB as model source nodes in the object tree, while manual/generated components remain editable component nodes.
9. Continue using database-backed draft/generated model persistence for MVP component instances, unless normalized component table work is already available.
10. Keep BOM and quote rollups connected to manual component metadata after edits.

## Testing Decisions

1. Add selection regression tests proving scene helpers and bounding boxes are not selected by normal viewport clicks.
2. Add component library tests proving required categories and Chinese labels render.
3. Add placement tests proving edited pre-placement defaults are applied to newly created wall, door, equipment and pipe components.
4. Add selected component editing tests proving rotation, dimensions and Chinese display name persist.
5. Add refresh/reopen tests proving rotation, lock state, visibility and renamed Chinese labels restore.
6. Add object tree tests proving generated, manual and IFC/GLB source nodes are grouped correctly.
7. Add IFC/GLB regression tests or browser smoke checks proving existing file open and model source loading still work after the UI change.
8. Add visual acceptance for desktop and mobile layouts to ensure the tool rail, component cards, object tree and property editor do not overlap.
9. Run existing focused viewer tests:
   - unified viewer shell
   - model source parity
   - component catalog
   - model CRUD
   - selected component editing
   - viewer summary
   - viewer acceptance smoke
10. Run `designer-workbench` build before claiming completion.

## Acceptance Criteria

1. Clicking in the 3D viewport no longer selects the outer scene boundary or helper frame as a business object.
2. Real components remain selectable and editable.
3. The left panel provides a design-software-like component library with vertical tool rail, category tabs and Chinese component cards.
4. Users can edit default component parameters before placement.
5. Users can place walls, doors/windows, equipment and pipes with those defaults.
6. Selected doors/windows/equipment can be rotated and saved.
7. Rotation, dimensions, position and Chinese display name restore after refresh/reopen.
8. The right panel no longer exposes “模型来源” as the primary debug card; it provides an object tree or layer-style model organization panel.
9. Object tree nodes use Chinese labels and support at least selection and visibility; lock state should be supported for MVP if it affects selection/editing.
10. IFC/GLB local open and backend model source open still work after the interaction changes.
11. Existing orbit, pan, zoom, fit-view and no-auto-rotate behavior remains intact.
12. Manual component changes continue to feed equipment summary, BOM entry and quote entry.
13. Focused viewer regression tests and `designer-workbench` build pass.

## Out of Scope

1. Full IFC element hierarchy extraction.
2. Editing geometry inside imported IFC/GLB files.
3. Parametric wall opening subtraction for doors/windows.
4. Multi-user live collaboration and conflict resolution.
5. Full keyboard shortcut system.
6. Full CAD snapping, dimension constraints and collision solver.
7. Replacing the current BIM viewer or model loader stack.

## Further Notes

This PRD is a follow-up to `3d能力整合.md`. It assumes the unified `4003/viewer` page, database-backed component CRUD, generated HVAC model, IFC/GLB opening, BOM/quote handoff and Chinese UI constraints already exist or are being retained.

The most important product rule is: this is an interaction and modeling workflow improvement, not a rewrite of the viewer. IFC/GLB import is a protected capability. The implementation should improve how imported sources appear in the unified object tree while preserving their current loading and review behavior.
