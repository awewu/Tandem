# Brand Product Category Management PRD

Status: draft-for-review
Date: 2026-07-24

## 背景

当前产品后台里，产品分类、官网菜单分类、系统字段混在一起使用，导致运营看到的分类不稳定：有时显示产品品类，有时显示官网二级菜单，有时又只能通过写死的 `家用 / 商用` 推断。品牌官网最终需要按分类组织产品，但现在缺少一个可维护的产品分类后台。

本 PRD 定义一个面向营销系统的产品分类管理能力。分类按品牌独立维护，用于承载每个子品牌官网产品的菜单结构和产品绑定关系。官网最终会读取这套分类，但本阶段先完成后台字段、数据模型、CRUD、产品绑定和列表展示能力，官网具体接入位置后续单独打通。

## 目标

1. 在产品模块中新增“产品分类”管理后台入口。
2. 每个品牌独立维护一套产品分类树。
3. 分类支持一级、二级、三级结构，所有层级都可以 CRUD。
4. 一级分类不写死，`家用 / 商用` 只是默认可配置项。
5. 二级分类表达对应系统，例如热水系统、地暖系统、全热新风、空气能热水器等。
6. 三级分类可选，用于系列、产品形态、容量段或更细菜单。
7. 产品可以绑定到分类路径，并在产品列表中展示完整分类。
8. 分类能力先服务后台管理和产品数据完整性，官网展示位置暂不在本期实现。
9. 第一版上线时需要按现有官网示例预写入一级、二级分类，避免分类后台初始为空；三级分类可暂不预置，由运营按需新增。

## 非目标

- 不做权限审批。
- 不做官网具体导航渲染接入。
- 不做拖拽排序，第一版可用排序数字。
- 不做多语言 SEO、分类落地页模板、专题页配置。
- 不重做产品列表整体 UI。
- 不改变产品上架、下架的官网货架语义。

## 核心概念

### 品牌独立分类树

每个品牌维护自己的分类树：

- Rheem 一套。
- Ruud 一套。
- Everhot 一套。
- 后续新增品牌时，创建该品牌自己的分类树。

品牌之间不继承、不共享、不互相污染。集团站是否聚合分类，后续单独设计。

### 分类层级

分类最多三层：

```text
一级分类
  二级分类
    三级分类
```

示例：

```text
Everhot 恒热
  家用
    家用中央空调
    地暖系统
    全热新风
  商用
    热水系统
      零冷水燃气热水器
      空气能热水器
    采暖系统
```

一级、二级、三级都不是写死枚举，后台均可新增、编辑、停用、删除和排序。

## 用户故事

1. 作为产品运营，我希望在产品模块里维护每个品牌自己的分类树，这样不同品牌官网菜单不需要共用一套写死分类。
2. 作为品牌运营，我希望一级分类也能新增和编辑，这样除了 `家用 / 商用` 之外，未来也能支持其他品牌自己的菜单结构。
3. 作为品牌运营，我希望二级分类表达具体系统，这样产品能挂到真实官网菜单下。
4. 作为品牌运营，我希望三级分类可选，这样需要细分系列或容量段时可以配置，不需要时可以不填。
5. 作为产品运营，我希望编辑产品时通过选择分类树绑定分类路径，而不是手填文本。
6. 作为产品运营，我希望产品列表显示完整分类路径，这样一眼能看出产品将来会落到哪个官网分类。
7. 作为运营负责人，我希望删除分类前能知道是否有产品正在使用，避免误删导致产品分类丢失。

## 页面与入口

在 `产品` 模块左侧导航新增：

```text
产品目录
产品资料
产品目录底座
产品分类
```

“产品分类”页面包含：

- 品牌切换：Rheem、Ruud、Everhot。
- 分类树区域：展示当前品牌的一级、二级、三级分类。
- 详情编辑区：编辑分类名称、编码、排序、状态、说明。
- 操作按钮：新增同级、新增下级、保存、停用、删除。

## 分类字段

建议新增品牌产品分类实体，字段如下：

| 字段 | 说明 |
| --- | --- |
| `id` | 分类 ID |
| `brandCode` | 品牌编码，如 `rheem`、`ruud`、`everhot` |
| `parentId` | 父分类 ID，一级分类为空 |
| `level` | 层级：1、2、3 |
| `code` | 分类编码，同品牌下建议唯一 |
| `nameCn` | 中文名称 |
| `nameEn` | 英文名称，可选 |
| `slug` | 官网路径或公开标识，可选 |
| `sortOrder` | 排序 |
| `status` | `active` / `inactive` |
| `description` | 后台备注，可选 |
| `createdAt` | 创建时间 |
| `updatedAt` | 更新时间 |
| `deletedAt` | 软删除时间 |

约束：

- 同一品牌下，同一父级的 `code` 不应重复。
- 分类最多三级。
- 二级必须挂在一级下面。
- 三级必须挂在二级下面。
- 停用分类不影响历史产品记录，但不应作为新产品绑定的默认可选项。

## 产品绑定字段

产品目录记录需要能保存分类路径。建议在产品品牌元数据中增加或统一以下字段：

| 字段 | 说明 |
| --- | --- |
| `categoryLevel1Id` | 一级分类 ID |
| `categoryLevel2Id` | 二级分类 ID |
| `categoryLevel3Id` | 三级分类 ID，可空 |
| `categoryPath` | 冗余展示路径，如 `家用 / 热水系统 / 空气能热水器` |

兼容策略：

- 旧字段 `category`、`websiteMenuCategory`、`system` 暂时保留。
- 新 UI 优先读取分类 ID 生成分类路径。
- 如果旧产品没有分类 ID，则用现有字段做兼容展示。
- 保存产品时，逐步写入新的分类 ID 字段。

## 产品编辑行为

产品编辑弹窗或页面中，分类选择改为三级联动：

1. 选择一级分类。
2. 根据一级分类加载二级分类。
3. 根据二级分类加载三级分类，三级可不选。

保存规则：

- 一级分类必填。
- 二级分类建议必填。
- 三级分类可选。
- 只能选择当前产品品牌下的分类。
- 停用分类不可作为新绑定选项；如果历史产品已绑定停用分类，编辑时要显示“已停用”提示。

## 产品列表展示

产品列表中的分类列显示完整路径：

```text
家用 / 热水系统
商用 / 热水系统 / 空气能热水器
```

如果产品还没有绑定新分类：

- 兼容显示旧字段推导结果。
- 可显示“未设置分类”。
- 不阻止产品保存，但官网发布前应提示分类不完整。

## 分类 CRUD 行为

### 新增

- 可新增一级分类。
- 可在一级下新增二级分类。
- 可在二级下新增三级分类。
- 不允许新增四级分类。

### 编辑

- 可编辑名称、编码、排序、状态、说明。
- 修改名称后，产品列表应展示新名称。
- 修改编码不应破坏已绑定产品，因为产品绑定使用分类 ID。

### 停用

- 分类可停用。
- 停用后不作为新产品绑定选项。
- 已绑定该分类的产品继续保留绑定，但列表显示“已停用”提示。

### 删除

- 第一版使用软删除。
- 没有产品绑定时允许删除。
- 已有产品绑定时不允许直接删除，应提示先迁移或清空产品绑定。
- 不做审批流。

## API 建议

新增品牌产品分类 API：

```text
GET    /api/v2/brand-product-categories?brandCode=everhot
POST   /api/v2/brand-product-categories
PATCH  /api/v2/brand-product-categories/:id
DELETE /api/v2/brand-product-categories/:id
GET    /api/v2/brand-product-categories/:id/usage
```

产品 API 需要支持：

- 查询产品时返回分类路径。
- 更新产品时保存分类 ID。
- 分类筛选可按一级、二级、三级分类 ID 过滤。

## 数据迁移建议

第一版必须做默认种子数据。默认种子数据按现有官网示例先预写入一级、二级分类；三级分类暂时不强制预写入，后续由运营在后台按需新增。

Everhot：

```text
家用
  家用中央空调
  地暖系统
  全热新风
商用
  热水系统
  燃气冷凝壁挂炉
  零冷水燃气热水器
  空气能热水器
  容积式燃气热水器
  电热水器
  采暖热水两联供
```

Rheem、Ruud 也需要预写入当前已有示例或现有后台可识别的一级、二级分类；如果某个品牌当前示例不完整，可以先写入最小可用树，后续由运营补全。

默认种子规则：

- 每个品牌至少应有一套一级、二级分类。
- 一级、二级来自当前官网或现有后台示例。
- 默认分类以 `active` 状态写入。
- 默认分类需要有稳定 `code` 和 `sortOrder`。
- 种子脚本应可重复执行，不应重复插入同一品牌同一父级下的同名或同 code 分类。
- 三级分类不是必填种子，除非现有官网已经有明确三级菜单。

迁移原则：

- 不破坏旧产品字段。
- 能自动匹配的旧字段自动绑定分类。
- 不能匹配的产品保持未绑定，并在列表中提示。

## 官网关系

官网最终按这套分类树组织产品：

- 一级分类对应官网顶层菜单。
- 二级分类对应系统或菜单分组。
- 三级分类对应可选下级筛选或细分菜单。

但本 PRD 第一阶段不实现官网具体渲染位置，不修改 Everhot/Rheem/Ruud 官网导航结构。只保证后台数据和产品绑定已经具备完整字段，后续官网接入时可以直接读取。

## 验收标准

1. 产品模块左侧出现“产品分类”入口。
2. 可以按品牌查看独立分类树。
3. 可以新增、编辑、停用、删除一级分类。
4. 可以新增、编辑、停用、删除二级分类。
5. 可以新增、编辑、停用、删除三级分类。
6. 不允许创建四级分类。
7. 产品编辑可以选择当前品牌下的一级、二级、三级分类。
8. 产品列表显示完整分类路径。
9. 已绑定产品的分类不允许直接删除。
10. 停用分类不再作为新产品绑定选项。
11. 旧产品未绑定新分类时仍能正常展示和编辑。
12. dealer-workbench build 通过。

## 建议拆分 Issue

1. 后端数据模型与迁移：新增品牌产品分类实体、表结构、种子数据。
2. 后端 CRUD API：分类树查询、新增、编辑、停用、删除、usage 检查。
3. 产品目录字段扩展：产品绑定分类 ID，查询返回分类路径。
4. 产品分类后台页面：左侧入口、品牌切换、分类树 CRUD。
5. 产品编辑绑定：三级联动分类选择，保存到产品记录。
6. 产品列表展示与筛选：显示完整分类路径，支持按分类筛选。
7. 兼容与回归：旧字段兼容、默认数据迁移、focused tests 与 build。
