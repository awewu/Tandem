# Official Site Product Detail Rich Content PRD

Status: draft-for-review
Date: 2026-07-29

## 背景

当前官网产品列表已经可以展示产品条目，但用户点击某个产品后，缺少完整的产品详情页内容承载能力。运营需要在后台为每个官网产品维护详情内容，前台官网在产品详情页读取并展示该内容。

本需求只服务官网产品详情展示，不用于商城、小程序交易页、购物车、下单或支付流程。

## 目标

1. 在产品新增/编辑能力中增加“官网产品详情”编辑区域。
2. 官网产品详情以富文本框形式维护，支持插入图片和基础图文内容。
3. 详情图片按 750px 宽度标准展示，高度/长度不限制。
4. 支持一张长图或多张详情图连续向下展示。
5. 详情内容必须保存到数据库，不能只保存在前端状态或静态文件中。
6. 官网用户点击产品后进入详情页，读取数据库中的详情内容并渲染。
7. 移动端展示时在不超过屏幕宽度的前提下等比例缩放，不能拉伸变形。

## 非目标

- 不做商城商品详情页。
- 不做小程序商品详情页。
- 不做价格、库存、购物车、下单、支付、优惠券等交易能力。
- 不做评价、问答、推荐商品、客服浮层等商城转化模块。
- 不做复杂 DAM 素材库、审批流、版本回滚和定时发布。
- 不改变现有产品列表、分类、上下架的核心语义，除非前台详情页读取需要最小接入。

## 用户故事

1. 作为官网运营，我希望在后台编辑产品时能维护该产品的详情内容，这样官网访客点击产品后可以看到完整介绍。
2. 作为官网运营，我希望可以上传 750px 宽的产品详情长图，这样能复用当前常见官网/电商详情图设计稿。
3. 作为官网运营，我希望详情图高度不受限制，这样一张完整长图可以从上到下自然展示。
4. 作为官网运营，我希望详情编辑器是富文本框，这样除了图片外还能补充文字、参数、安装说明、售后说明等内容。
5. 作为官网访客，我希望点击产品后看到清晰、居中的详情内容，而不是只看到产品列表摘要。
6. 作为系统维护者，我希望详情内容保存在数据库中，这样产品数据迁移、备份和接口读取都有稳定来源。

## 功能范围

### 后台编辑

产品新增/编辑页增加“官网产品详情”区域：

- 使用富文本编辑器。
- 支持插入图片。
- 支持基础文本格式：标题、段落、加粗、列表、链接、表格或参数说明。
- 支持图片预览。
- 支持删除详情内容中的图片引用。
- 支持调整详情图在富文本中的展示顺序。
- 保存产品时同时保存详情内容。

详情编辑区域文案建议：

```text
官网产品详情
建议上传宽度 750px 的详情图片，高度不限；移动端将按屏幕宽度等比例缩放。
```

### 图片规则

- 推荐上传图片宽度：750px。
- 展示最大宽度：750px。
- 高度不限制。
- 多张图片按富文本中的顺序从上到下展示。
- 图片必须保持原始比例，不允许被强制拉伸。
- 前台容器居中展示。
- 小屏幕下使用 `max-width: 100%` 自适应。
- 后台可提示格式限制，例如 `png`、`jpg`、`jpeg`、`webp`，具体格式以现有上传能力为准。

### 官网前台展示

官网产品列表点击产品后进入产品详情页：

- 根据产品 ID 或 slug 请求产品详情数据。
- 展示产品基础信息，例如名称、型号、分类、封面图等，沿用现有官网样式。
- 展示数据库中保存的官网产品详情富文本。
- 详情正文区域最大宽度 750px，水平居中。
- 长度不限制，页面自然纵向滚动。
- 富文本内图片宽度不超过 750px，移动端不超过屏幕宽度。
- 无详情内容时展示合理空态，避免页面空白或报错。

## 常见官网详情内容建议

结合当前需求，第一版详情页重点承载图文内容，不做商城交易模块。运营可在富文本中组织以下内容：

- 产品首屏卖点图。
- 产品核心优势说明。
- 产品规格参数表。
- 使用场景或系统应用说明。
- 安装条件、安装示意或注意事项。
- 品牌说明，例如 Rheem / Ruud / Everhot。
- 售后、质保、服务支持说明。
- 认证、标准或适用规范说明。
- 产品细节图、结构图、尺寸图。
- FAQ 或购买前注意事项。

## 数据模型建议

在产品主记录或官网产品展示扩展记录中增加详情字段。字段归属应遵循当前产品目录和品牌官网模块的既有边界。

建议字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `officialDetailHtml` | text | 官网产品详情富文本 HTML，保存图片地址和图文结构 |
| `officialDetailUpdatedAt` | datetime | 官网详情最后更新时间 |
| `officialDetailUpdatedBy` | string | 最后编辑人，可选 |

如果现有系统已存在产品官网展示扩展表或 MongoDB 文档扩展字段，优先复用现有结构，不强行新建重复模型。

图片文件本身通过现有上传/静态资源能力存储，数据库中的富文本 HTML 保存图片 URL。不得只把详情图片存在浏览器本地或临时内存中。

## API 建议

后台产品保存接口需要支持官网详情字段：

```text
POST/PATCH /api/v2/products/:id
```

请求体可增加：

```json
{
  "officialDetailHtml": "<p>...</p><img src=\"...\" />"
}
```

官网前台产品详情接口需要返回：

```json
{
  "id": "product-id",
  "name": "产品名称",
  "model": "型号",
  "officialDetailHtml": "<p>...</p><img src=\"...\" />"
}
```

如果当前前台已有产品详情接口，应在既有响应中扩展字段，避免额外创建平行接口。

## 安全与内容约束

- 后端保存富文本前应做 HTML 白名单清洗，避免脚本注入。
- 前台渲染富文本时不得直接执行脚本。
- 图片 URL 应限制为可信上传域、站内静态资源或已允许的 CDN。
- 富文本允许的标签建议包含：`p`、`br`、`strong`、`b`、`em`、`i`、`ul`、`ol`、`li`、`table`、`thead`、`tbody`、`tr`、`th`、`td`、`a`、`img`、`h2`、`h3`、`h4`。
- `img` 标签必须带 `src`，建议补充 `alt`。
- 前台样式需要统一限制 `.product-detail-content img { max-width: 750px; width: 100%; height: auto; }` 或等效规则。

## 验收标准

1. 后台产品新增/编辑页出现“官网产品详情”富文本编辑区域。
2. 可以在富文本中上传并插入详情图片。
3. 上传 750px 宽长图后，后台预览不变形。
4. 保存产品后刷新后台页面，详情内容仍然存在，证明已从数据库读取。
5. 官网产品列表点击产品后可以进入该产品详情页。
6. 官网详情页展示数据库中的富文本详情内容。
7. 详情页正文最大宽度为 750px，页面居中展示。
8. 长图高度不受限制，页面可以自然向下滚动。
9. 移动端图片不超出屏幕宽度，且不变形。
10. 没有详情内容的产品不会报错，并显示合理空态或仅展示基础信息。
11. 富文本中的脚本或危险属性不会在前台执行。
12. 相关产品/backend/官网展示变更通过对应现有测试或守卫；无法运行的门禁需明确记录。

## 建议拆分 Issue

1. 数据模型与迁移：为产品记录增加官网详情富文本字段，并确保生产数据库持久化。
2. 后台编辑器接入：产品新增/编辑页增加官网产品详情富文本框和图片插入能力。
3. 上传与图片样式规则：复用现有上传接口，约束详情图最大展示宽度 750px、高度自适应。
4. 后台保存与回显：产品保存接口接收详情 HTML，编辑页重新打开可从数据库回显。
5. 官网详情页接口：产品详情 API 返回 `officialDetailHtml`。
6. 官网前台渲染：产品列表点击进入详情页，居中展示 750px 宽富文本内容。
7. 安全清洗与测试：增加富文本白名单、安全渲染、图片响应式和数据库持久化验证。

## 需求复述

本需求是在官网产品体系中增加产品详情能力。后台产品新增/编辑时提供“官网产品详情”富文本框，运营可以上传并插入宽度按 750px 标准设计的详情长图，图片高度不限，也可以补充文字、参数、安装说明、售后说明等图文内容。保存时详情内容必须写入数据库。官网用户从产品列表点击某个产品后进入详情页，页面读取数据库中的富文本详情内容，按最大 750px 宽、居中、长图自然向下滚动的方式展示。该功能不用于商城或小程序交易详情页。
