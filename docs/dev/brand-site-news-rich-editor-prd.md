# PRD：品牌官网资讯运营编辑器

## 1. 背景

当前品牌官网资讯管理已经具备基础 CRUD、封面、摘要、正文、状态和官网列表展示能力，但正文编辑仍接近基础富文本框，尚未达到运营人员日常发布官网资讯的使用标准。

运营发布一篇官网资讯时，通常需要组织标题层级、段落、列表、引用、链接、正文图片、图片尺寸、图片对齐、图注和发布前检查。后台编辑区、后台详情预览和官网详情页必须保持一致，否则运营无法确认最终发布效果。

本 PRD 是 `docs/dev/brand-site-news-management-prd.md` 的二期补充，聚焦“资讯正文运营编辑器”和“详情页一致渲染”。

## 2. 目标

- 将官网资讯正文从基础输入升级为运营可用的资讯发布编辑器。
- 保证编辑区、后台详情预览、官网详情页三处内容和样式一致。
- 保持当前 Rhautt Nexus 控制台 VI 和 Everhot 官网视觉风格，不引入另一套视觉体系。
- 降低运营发布成本，避免因代码修改才能维护新闻正文。

## 3. 用户与场景

### 3.1 主要用户

- 品牌运营：创建、编辑、发布官网资讯。
- 市场人员：维护活动新闻、产品动态、服务公告、案例文章。
- 管理员：审核发布状态、隐藏或归档过期资讯。

### 3.2 典型场景

- 发布新品上线新闻，需要封面、正文产品图、分段标题和 CTA 链接。
- 发布展会新闻，需要活动现场图、图注、项目列表和引用语。
- 发布服务公告，需要清晰的小标题、编号列表和外部/内部链接。
- 修改已发布资讯，需要后台预览和官网最终效果一致。

## 4. 范围

### 4.1 本期范围

- 正文富文本编辑。
- 标题层级：段落、H2、H3。
- 基础格式：加粗、斜体、项目列表、编号列表、引用、链接。
- 正文图片上传。
- 正文图片尺寸：小、中、大、满宽。
- 正文图片对齐：左、中、右。
- 正文图片图注。
- 图片选中后的编辑工具：尺寸、对齐、图注、替换、删除。
- 后台卡片预览和详情预览。
- 官网新闻详情页渲染正文。
- 发布前校验。
- HTML 白名单清洗。

### 4.2 暂不做

- 多人协作编辑。
- 版本历史和回滚。
- 定时发布。
- 视频和复杂媒体嵌入。
- 拖拽式自由排版。
- Markdown 模式。
- 多语言工作流。
- AI 自动生成全文。

## 5. 功能需求

### 5.1 正文编辑器

编辑器必须支持：

- 段落正文。
- H2 标题。
- H3 小标题。
- 加粗。
- 斜体。
- 项目列表。
- 编号列表。
- 引用块。
- 链接插入和编辑。
- 正文图片上传和插入。

编辑器体验要求：

- 光标不能回弹到正文开头。
- 点击工具栏不能造成编辑区闪烁或整体刷新感。
- 工具栏必须作用于当前选中文字或当前光标所在段落。
- 输入过程不应频繁重写编辑 DOM。
- 预览可以延迟同步，但保存必须使用最新正文。

### 5.2 图片编辑

正文图片和封面图必须区分：

- 封面图：用于新闻卡片和详情页顶部大图。
- 正文图：用于文章内容中间。

正文图片必须支持：

- 上传 PNG/JPG。
- 插入到当前光标位置。
- 保持图片比例。
- 尺寸：小、中、大、满宽。
- 对齐：左、中、右。
- 图注：可选。
- 替换图片。
- 删除图片。

推荐数据属性：

- `data-size="small|medium|large|full"`
- `data-align="left|center|right"`
- `data-caption="..."`

图注展示规则：

- 后台编辑区可以以内联控件编辑图注。
- 后台详情预览和官网详情页展示为图片下方小号灰色说明。
- 没有图注时不占位。

### 5.3 标题与段落

工具栏不应只有 H2。至少提供：

- 段落。
- H2：文章主要小节标题。
- H3：小节内标题。

展示规则：

- 后台编辑区、详情预览、官网详情页的 H2/H3 字号可以略有差异，但层级关系必须一致。
- 不允许正文区域使用页面级 H1，H1 保留给详情页文章标题。

### 5.4 链接

链接能力要求：

- 对选中文字插入链接。
- 未选中文字时插入链接 URL 文本。
- 支持站内相对路径。
- 支持 `https://`、`mailto:`、`tel:`。
- 外链自动加 `target="_blank"` 和 `rel="noopener noreferrer"`。
- 禁止 `javascript:` 等不安全协议。

### 5.5 预览

后台必须提供两个预览：

- 卡片预览：模拟首页/资讯列表卡片。
- 详情预览：模拟官网新闻详情页。

预览要求：

- 摘要只影响卡片和详情摘要。
- 正文只影响详情正文。
- 正文图片尺寸、对齐、图注必须和官网详情页一致。
- 无封面时显示当前默认占位图，不影响正文预览。

### 5.6 发布校验

当状态为 `published` 时，保存/发布前至少校验：

- 标题必填。
- 摘要必填。
- 发布日期必填或自动补当前日期。
- 封面图必填。
- 正文不能为空。
- 正文图片 URL 必须是允许来源。

建议提示但不阻断：

- 摘要过长。
- 正文没有图片。
- slug 为空时自动生成。

## 6. 数据与安全

### 6.1 正文存储

本期建议继续保存为受限 HTML，而不是结构化 JSON。原因：

- 当前后端已有 `body` 字段。
- 官网静态前端消费成本低。
- 能快速支撑运营发布。

后续如果需要拖拽模块、模板化段落、多语言或 AI 分块生成，再评估结构化 JSON。

### 6.2 HTML 白名单

允许标签：

- `p`
- `br`
- `strong`
- `b`
- `em`
- `i`
- `ul`
- `ol`
- `li`
- `a`
- `h2`
- `h3`
- `blockquote`
- `figure`
- `figcaption`
- `img`

允许属性：

- `a.href`
- `a.target`
- `a.rel`
- `img.src`
- `img.alt`
- `img.loading`
- `img.data-size`
- `img.data-align`
- `figure.data-size`
- `figure.data-align`

禁止：

- `script`
- inline event handler，例如 `onclick`
- inline style
- `javascript:` URL
- iframe

### 6.3 图片来源

允许：

- `/api/v2/file-artifact/...`
- `/assets/...`
- `https://...`
- 开发态可接受 `blob:` 或 `data:image/...`，保存前应尽量转为 file artifact。

生产建议：

- 正文图片最终使用 file artifact。
- 外链图片可作为后续策略，不建议默认依赖。

## 7. UI/VI 要求

### 7.1 后台控制台

必须沿用现有：

- `btn`
- `btn-outline`
- `btn-brand`
- `input`
- `product-edit-section`
- `site-news-edit-section`
- 当前红色品牌色和表单边框体系。

编辑器工具栏：

- 使用 lucide 图标。
- 图标按钮带 tooltip/title。
- 图片尺寸/对齐可使用紧凑 segmented controls。
- 不使用大面积装饰卡片。

### 7.2 官网详情页

必须沿用 Everhot 当前官网：

- 白底详情内容。
- Everhot 红色链接。
- 当前新闻卡片边框、圆角、阴影口径。
- 当前字体和段落行高。

不允许：

- 新增一套营销页视觉。
- 使用大面积渐变背景。
- 图片样式破坏现有官网节奏。

## 8. 验收标准

### 8.1 编辑体验

- 在正文末尾输入，光标不跳回开头。
- 选中文字后点击加粗，只有选中文字变粗。
- 选中文字后点击 H2/H3，对应段落变为标题。
- 点击工具栏不会出现编辑区整体刷新感。
- 粘贴纯文本后格式稳定。

### 8.2 图片体验

- 可以上传正文图片。
- 图片插入到当前光标位置。
- 点击图片后出现尺寸和对齐编辑能力。
- 小/中/大/满宽保存后仍保持。
- 左/中/右对齐保存后仍保持。
- 图注保存后在详情预览和官网详情页展示。
- 可以替换和删除正文图片。

### 8.3 预览与官网

- 后台详情预览和官网详情页正文一致。
- H2/H3、列表、引用、链接、图片、图注显示一致。
- 新闻卡片仍只展示封面、日期、标题、摘要。
- 正文不会影响卡片布局。

### 8.4 安全与数据

- 不安全标签被清洗。
- 不安全 URL 被清洗。
- 保存后的正文 HTML 只包含白名单标签和属性。
- 发布状态下缺少必填项会阻止保存或发布。

## 9. 建议实施步骤

### Phase 1：稳定编辑器

- 改为非受控 contentEditable。
- 输入时不清洗 DOM。
- 保存和预览同步时再清洗。
- 修复光标回弹和工具栏刷新感。

### Phase 2：完善文本格式

- 增加段落、H2、H3。
- 增加引用。
- 修复链接插入和编辑。

### Phase 3：完善图片能力

- 正文图片上传。
- 图片尺寸。
- 图片对齐。
- 图注。
- 替换和删除。

### Phase 4：统一渲染

- 后台详情预览和官网详情页共用同一套内容 CSS 规则。
- 官网前端清洗保留 `data-size`、`data-align`、`figure/figcaption`。

### Phase 5：验收门禁

- `npm --prefix apps/dealer-workbench run build`
- `node --check apps/everhot-cn/public/js/site-news.js`
- `npm run guard:frontend-api-contract`
- `npm run guard:rheem-vi-production:strict`

如果 VI 严格门禁因既有全站品牌锁定语言失败，必须在交付说明中明确报告，并区分是否由本功能引入。

## 10. 开放问题

- 正文外链图片是否允许生产使用，还是必须全部上传为 file artifact？
- 图注是否只支持纯文本，还是允许链接？
- 是否需要 SEO 独立字段：SEO title、SEO description、canonical URL？
- 是否需要发布审核角色，而不是运营直接发布？
- 是否需要定时发布作为下一期能力？
