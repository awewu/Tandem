# HR 预算 — FP&A — 组织编制 闭环架构

> 状态：草案 v0.1（架构设计，不含实现代码）
> 受众：CFO / CHO / 经营班子（经营治理视角）
> 配套：`docs/PERFORMANCE-MODULE-PRD.md`（薪酬绩效模块，产品/研发视角）
> 一句话定位：把"薪酬结构"上升为"经营治理体系"——用 FP&A 主账、HR 执行账、组织编制桥，三环闭环地管住人工成本、放开价值分享。

---

## 0. 核心命题

薪酬结构定好之后，真正决定它能否可持续运转的，是三个系统的关系：

- **FP&A**（财务计划与分析）—— 财务真相与预算主数据。
- **HR 预算体系** —— 人工成本的执行与明细账。
- **组织结构 + 人头编制** —— 把"钱"翻译成"人和岗"的桥。

本文回答：它们如何**体系化**、如何**闭环**。

---

## 1. 根本关系：FP&A 是主账，HR 预算是执行明细账

- **FP&A 拥有**：收入/成本/利润预算、每个 BU/产线的**公允线**、**人工成本包（labor cost envelope）**。人工成本包是 P&L 的一条大科目，按"占收入比"或 driver-based 设定。
- **HR 预算体系拥有**：把人工成本包翻译成 `编制 × 职级带宽 × 分享计提` 的结构化明细。
- **铁律**：HR 预算 bottom-up 必须落在 FP&A top-down 的包以内；每个节点强制对账，差异留痕审批。

### 1.1 两类薪酬的资金来源必须分离（架构分野）

| 类型 | 资金来源 | 方向 | 会计处理 |
|---|---|---|---|
| **固定薪酬（地板）** | 人工成本包切出 | top-down 预算制 | 预算科目，编制×带宽算死 |
| **增值分享（线上）** | `(实际−预算)` 真实超额 | bottom-up 自筹制 | **不占固定包**，FP&A 侧 accrual 计提 |

> **制度红线**：分享池不是预算科目，是 **FP&A 随 actuals 滚动的 accrual（计提负债/费用）**。否则年底要么发不出、要么穿包。

## 2. 组织结构 + 编制 = 焊死两账的桥

```
FP&A 人工成本包（钱）
        ↕  ←—— 桥：组织结构 + 编制 ——→
薪酬结构 带宽表（单价/规则）
        =
编制(HC) × 职级带宽 = 固定人工成本预算（与包对账的唯一口径）
```

- **组织结构** → BU/部门/产线/岗位序列 → 直接映射**四族**：
  - 生产线 → LIP · 销售/售后/零售 → SIP · 经营者/责任人 → MIP · 专业/职能 → AIP
- **编制** → 每个岗位序列按职级核定的人数。
- **编制 × 带宽 = 固定人工成本** → HR bottom-up 的算法，也是与包对账的唯一口径。

**四族 → 组织单元 → 公允线 天然对齐**：

| 族 | 组织单元 | 公允线口径 | 分享池归属 |
|---|---|---|---|
| LIP | 产线/班组 | 财务测算产线基数 | 部门奖金池 |
| SIP | 销售单元 | 销售目标/达成率 | 提成池 |
| MIP | BU/公司 | 预算利润/预算销售 | 增值分享池 |
| AIP | 职能/项目 | OKR/专业交付 | 季度激励+S1池 |

> 组织结构一变，公允线归属与分享池归属**自动跟着迁移**（见 §6.3 组织变更迁移规则）。

## 3. 三环闭环

```
┌─── 环1 规划环（年度, top-down）────────────────┐
│ 战略/经营目标 → FP&A财务预算(含人工成本包)        │
│   → 按BU/产线分解包 → HR依组织做编制规划          │
│   → 编制×带宽=固定成本 →【对账闸门】≤包?          │
│   → 差异协商(增编需ROI/减编) → 冻结编制+批准       │
└──────────────────┬───────────────────────────┘
                   ↓
┌─── 环2 执行环（期中/期末, bottom-up）───────────┐
│ FP&A actuals(实际利润/收入) → 比公允线 → 超额=增值 │
│   → 按族公式计提分享池(accrual) → L3结算引擎发放   │
│   → 实际人工成本(固定+分享)回记FP&A                │
└──────────────────┬───────────────────────────┘
                   ↓
┌─── 环3 反馈环（校准）──────────────────────────┐
│ 实际人工成本 ÷ 实际产出 → 人效指标               │
│   (人均产值/人均利润/人工成本率/编制利用率)        │
│   → 评估编制合理性+组织效能 → 校准公允线(baseline) │
│   → 反哺环1下年度编制与预算                       │
└───────────────────────────────────────────────┘
```

- **环1 规划环**：战略 → 财务预算 → 编制 → 对账 → 批准。
- **环2 执行环**：实际结果 → 超额增值 → 分享计提 → 结算发放（对接 PRD §8 L3 结算层）。
- **环3 反馈环**：人效反馈 → 公允线校准（挂 `lib/governance/delivery-baseline.ts` / `baseline-calibration.ts`）→ 反哺下年度。

> **公允线不是拍一次，是被人效反馈持续校准的。**

## 4. 体系化的五根支柱

- **① 统一主数据（single source of truth）**：组织树、职级带宽表、编制表、四族映射——**FP&A 与 HR 共用一套，绝不各存一份**。这是不闭环的头号杀手。
- **② 对账闸门（reconciliation gates）**：每个规划/结算节点，HR bottom-up 与 FP&A top-down 强制对账，差异留痕审批。
- **③ 人工成本包治理（envelope governance）**：包按 driver 设定；增编/调薪/晋升/分享计提**都从包里实时扣减**，headroom 随时可见。
- **④ 分享池 accrual 机制**：实际超预算时按族公式**实时计提挂账**，随 actuals 滚动，杜绝年底穿包。
- **⑤ 编制-带宽-预算三表联动**：`编制表 ↔ 带宽表 ↔ 成本预算`，任一变动联动重算并触发对账。

## 5. 人头编制生命周期闭环

编制是防止人工成本失控的**控制杆**，自成小闭环：

```
定编(规划核定) → 用编(招聘/onboarding占编) →
控编(在岗 vs 编制: 空编/超编告警) →
核编(人效评估: 编制产出够不够) → 调编(下年度增/减)
```

- **超编 = 硬闸门**：占满编制不得新增，防穿包。
- **空编预算去向（已定治理参数）**：空编省下的钱**默认收回 / 转招聘，不得转入分享池**——防止"故意不招人套现"扭曲反禀赋。此项为可调治理参数，调整需经 FP&A + HR 联合审批。

## 6. 治理与所有权

### 6.1 谁拥有什么

| 对象 | Owner | 说明 |
|---|---|---|
| 人工成本包 / 公允线 | FP&A | 财务主数据 |
| 编制表 / 职级带宽 | HR | 执行明细 |
| 增编 ROI 论证 | 业务 BU | 谁要人谁举证 |
| 分享池 accrual 确认 | FP&A | 确认 actuals 真实 |

### 6.2 变更流程（示例：增编）

```
业务提增编+ROI → HR核带宽算成本 → FP&A核包headroom
  → 有headroom? → 联合审批 → 更新编制表 → 重算三表对账
  → 无headroom? → 战略重议 / 减编置换 / 驳回
```

### 6.3 组织变更迁移规则

BU/产线重构时，须定义：公允线与分享池归属迁移、在途编制归属、未结算分享的清算与迁移——留痕可回溯。

## 7. 必须正视的三个张力

- **双轨 A 轨升职 vs 成本包约束**：述职升职级→加薪→占包，**晋升受 headroom 约束**（"能升但没钱升"会架空双轨）。
  - 缓解：晋升独立预留小池 / 晋升与减编-汰换联动（升一个、汰一个）。
- **分享 accrual 真实性 vs sandbagging**：包越紧，业务越有动机压低预算把"超额"做虚套池。
  - 缓解：分享计提须经 FP&A 确认 actuals 真实（"增值成色"护栏）。
- **组织重构的归属漂移**：见 §6.3 迁移规则。

## 8. 与薪酬模块 PRD 的接口

- 本架构的 **L1 数据层**（FP&A actuals/预算、编制、带宽）= PRD §2 三层引擎的数据层输入。
- 本架构的 **人工成本包 + 编制** = PRD §5 双轨轮动、§8 结算的预算约束边界。
- 本架构的 **环2 分享计提** = PRD §8 L3 结算层的资金来源与 accrual 保障。
- 本架构的 **环3 校准** = PRD §1 P2 公允线的动态来源。

## 8.1 薪酬域数据抓取契约（已预设，`lib/comp/fpa-extract.ts`）

FP&A 从薪酬域抓取预决算数据的**稳定接口**（PMS 同款直连 `comp_*` typed 表，SQL 层聚合；结算未生成时返回零值行，保证 FP&A 侧稳定接入）：

- **`plannedBudgets(tenantId, period)`** → 部门人力预算池（`comp_budget_pool` 部门基数/上限/硬悬崖）。
- **`fixedPayrollForecast(tenantId)`** → 固定薪资承诺预测 = Σ 在职 `comp_employee_grade` × `comp_grade_band`（基本+技能缓存+当前任务档 A–G），出 `headcount / 月度 / 年度`。
- **`actualPayroll(tenantId, period)`** → 周期实发决算（`comp_monthly_settlement` 汇总：基本/技能/任务/绩效/合计）。
- **`budgetVsActual(tenantId, period)`** → **预决算对比核心指标**（planned 固定承诺 vs pool 基数 vs actual 实发 → variance / varianceRate）。

> 说明：技能工资在预测中取 `grade_band.skillWageCached`（HR 改价后由 `refreshBandSkillWageCache` 刷新），权威真源仍是 `comp_skill_def` 的实时 Σ定价。
