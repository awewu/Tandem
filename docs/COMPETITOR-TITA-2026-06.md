## 一、Tita 产品哲学:绩效管理闭环四阶段

Tita 把自己定位为**绩效管理闭环平台**(而非单一 OKR 工具)。其快捷导航图揭示全产品按 4 阶段组织,这是理解其所有模块的总纲:

```
1 立目标  ──▶  2 抓过程  ──▶  3 拿结果  ──▶  4 持续辅导与成长
  OKR          项目/计划表/总结   员工绩效/360     一对一面谈/Learning
                         （贯穿: 数据驾驶舱 + 报表）
```

| 阶段 | Tita 模块 | 内涵 |
|---|---|---|
| **1 立目标** | OKR(对齐/复盘/案例库) | 目标制定与对齐 |
| **2 抓过程** | 项目(里程碑/甘特/人力排期)、计划表(日周月排工作)、总结(日/周/月报) | 执行过程管控 |
| **3 拿结果** | 员工绩效(KPI/价值观/PBC)、360 评估 | 结果评估 |
| **4 持续辅导成长** | 一对一面谈、Learning | 反馈与成长 |
| **贯穿** | 数据驾驶舱、报表 | 数据驱动决策 |

**护城河**: 广度(全链路覆盖)+ 配置化(规定中台)+ 过程管控深度(尤其阶段 2)。

## 二、逐模块情报地图(~20 屏)

### 阶段 1 · 立目标

- **OKR 列表**: 组织树(按体系)× 周期筛选;支持 AI 创建;把「本周工作」「未来四周工作计划」也建模为 Objective(带 KR / 信心分 / 进度环 / AI 洞察)。
- **OKR 仪表盘**(管理者驾驶舱): 三段 Tab(设定/追踪/结果分析)。核心指标:**填写率 6%、目标对齐率 21%、E-执行分解率 0%**;提交/审批漏斗;分布环图(每人 O 数:106 人中 100 人未设置;每 O 的 KR 数)。
- **目标对齐「全景作战图」**(皇冠): 四列贯穿 **公司目标 → 部门目标拆解 → 项目承接 → 兵力分配(人数 + 人天 4584)**;AI 洞察自动揪"6 个风险目标、3 个风险项目";AI 批量生成。

### 阶段 2 · 抓过程(我方最大缺口)

- **工作法**(周节奏驾驶舱): 选定一个 O,四象限 = 本周工作 / OKR(智能拆解器)/ 未来四周计划 / 当前进展;下属切换;把 KR 拆成本周可执行事项并回写进展。
- **项目**(一级执行体,11 个子 Tab): 任务/里程碑/看板/甘特图/人力排期/流程图/统计/动态/文件/概览/外部协作。
  - **甘特图 + WBS**: 里程碑→任务,周时间轴。
  - **看板**: 按里程碑分列。
  - **人力排期(容量)**: 人 × 天负荷热力图,表情表负荷(😍 有余力 / 😣 超载),`44/22` = 200% 超载。
  - **统计**: 任务完成率、按负责人进展、里程碑完成度、人员统计。
  - **概览**: **进度基准线(baseline)** vs 实际进度 → 风险%(如实际 60.94% vs 预期 93% → 风险 80.94%);进度趋势图;操作记录(审计)。
  - **动态**: `Tita小助手` 每日自动播报进度("60.94% ↑1.25%")。
  - **添加任务**: 从任务池复用任务(任务↔项目多对多)。
  - **项目集(Portfolio, NEW)** + AI 创建 + 项目模板库 + 项目风险视图。
- **任务中心**: 强筛选(类型/审批状态/是否过期/分类)+ 多视角(我的/下属/公司全部)+ 审批流 + 优先级 P1-P3 + 进度%。
- **总结(日/周/月报)**: 模板 + 组织/群组视角 + 总结仪表盘 + 提交率追踪。

### 阶段 3 · 拿结果

- **员工绩效**: HR 工作台、考核管理、**考核模板**、**企业指标库**(指标定义 SSOT,按体系分类:营销体系/运营体系/系统指标;可复用、被考核模板引用)、考核设置。
- **绩效仪表盘**: 参与度分析/结果分析/指标分析、考核阶段人次汇总、**部门推进对比**、**AI 绩效报告**、自由导出报表。
- **360 评估**: 全方位多维度。

### 阶段 4 · 持续辅导成长

- **一对一面谈**: 模板驱动(绩效面谈改进/每周快谈对齐/目标制定)+ 行动计划 + 历史面谈留痕。
- **Learning**: OKR/绩效使用学习。

### 贯穿 · 数据与配置

- **首页工作台(AI 风险驾驶舱)**: 进门第一屏即 AI 风险摘要("177 个目标严重滞后、22 个风险 KR、8 个逾期项目、1523 个逾期任务");任务概览;日报提交率;OKR 概览(完成度 15% / KR 更新率 42%);团队任务饱和度热力图;快速新建。
- **复盘**: 独立模块,组织树 + 周期筛选 + 可见性控制(仅相关成员可见)+ 社交互动(点赞/评论)+ 周期标签。
- **企业管理规定(配置中台)**: OKR 规定(周期/制定/执行/评分设置)、项目规定、计划/日报/周报/月报规定、任务类型/审批配置、项目类型/审批配置。

## 四、差异化打法(不拼广度,拼 AI 主动性 + 经营深度)

Tita = 配置化 + 人工驱动 + 过程管控广度。我方反制三板斧:

1. **AI 不只暴露问题,而是处置问题**
   - Tita 风险驾驶舱只显示"V1 项目投入最多请关注";我方可直连**议事(convergence/DC)+ FP&A**,给出"该风险项目的决策卡 + 对 BSC 利润影响投影 + 建议调谁补位"。
2. **人天 × 利润 ROI 闭环(Tita 给不了)**
   - 容量(人天,来自 `Initiative.estimatedHours`)接上 **FP&A(KR→BSC delta)**,算"投 N 人天换多少利润改善"。这是把"目标"做成"经营账"的独家能力。
3. **过程零负担(把 Tita 的"填写率焦虑"反向变卖点)**
   - 日报/复盘/Check-in/进度播报**全部 AI 起草初稿**,员工只需修订确认。Tita 靠"98% 优秀员工都在填"的话术驱动,我方靠"AI 已帮你写好"。

## 六、可直接动手的设计:进度基准线风险算法

**为什么最高杠杆**: 一个纯函数,零新数据(仅用 `Cycle` 日期 + 进度),却能同时支撑 P0 的健康看板、首页驾驶舱,以及 P1 项目模块的风险分。把现状"人工 confidence 红黄绿"升级为"客观进度偏差"。

**Tita 算法本质**(从 V4 项目概览反推):
```
风险 = 时间进度基准 − 实际进度  (schedule variance)
实际 60.94% vs 预期 93% → 落后 32% → 高风险
```

**建议落点**: `lib/okr/risk.ts`(新增纯函数,可被 OKR/项目/看板共用)

```ts
export interface RiskReport {
  expectedProgress: number;   // 0-100, 按时间应完成
  actualProgress: number;     // 0-100, 实际
  variance: number;           // expected - actual, 正=落后
  band: 'on-track' | 'at-risk' | 'off-track';
  daysElapsed: number;
  daysTotal: number;
}

// 阈值建议: variance <= 10 绿; 10 < variance <= 25 黄; > 25 红
export function calcScheduleRisk(opts: {
  startDate: number; endDate: number;
  actualProgress: number; now?: number;
}): RiskReport { /* 纯计算, 见实现 */ }
```

**应用点**:
- OKR 健康看板: 把 Objective 的 confidence 旁边加"客观风险"列。
- 首页驾驶舱: 聚合所有 active Objective 的 `off-track` 数 → "X 个目标严重滞后"。
- 项目模块(P1): 项目进度 vs 项目周期基准 → 项目风险%。

## 七、可直接动手的设计:工作法(周节奏驾驶舱)

**复用度极高**: Objective/KeyResult/Initiative/CheckIn/AI 网关/org 树全部现成,唯一缺 `Initiative.horizon`。

**数据层最小改动**(`lib/store/okr.ts` Initiative 接口):
```ts
horizon?: 'this-week' | 'next-4-weeks' | 'backlog';
weekOf?: number;  // 该周起始时间戳, 跨周归档用
```
> 亦可不加字段,纯用 `dueDate` 落点自动分桶;加字段更显式稳定。

**视图层**(`app/work-method/page.tsx`,四象限):
- OKR 面板: 复用 `selectedKRs` + 进度环
- 本周工作 / 未来四周: 按 `horizon`(或 `dueDate`)过滤 `initiatives`,复用 `OKRInitiatives`
- 当前进展: 复用 Check-in 弹窗(`setCheckinFor`)

**AI 智能拆解器**(差异化): 输入 O + KR + 上周进展 → 输出本周建议 3-5 件 Initiative(自动挂 KR),结合 Check-in 障碍 + 信心趋势排序。接 TAF/LLM 网关。

## 十、进化思路与重构债(代码实测版 · 2026-06-25)

> 落地前对 OKR 域做了代码实测,据此修正基线。结论:存量被低估,阶段 1「立目标」已基本完整。

### ① 已经有了(无需重做,或仅增强)

- 路由: `app/okr`、`dashboard`(部门聚合)、`cascade`(5层穿透)、`calibration`、`fpa`、`calendar`
- 引擎: `lib/okr/` 11 模块 — `health`(Hygiene)、`diagnosis`、`rollup`+`execution-rollup`、`cadence`、`trend`、`quality`、`scoring`、`templates`、`visibility`(读权限)
- 组件: `components/okr/` 14 个(含 `bulk-create-dialog` AI 起草、`alignment-tree`、`tti-panel`、`monthly-comparison`)
- 后端: `tandem-okr`、`key-results`、`initiatives`、`checkins`、`cycles`、`me/okr-health`、`admin/governance/okr-drift`、`analytics/okr-kpi-consistency`

### ② 我们做得更好(护城河)

AI 起草 4 套 OKR · FP&A 锚定(KR→BSC,Tita 无)· 三省六部治理 + drift 检测 · cascade 决策卡(DC)穿透 · Learning AI 课程 · OKR↔KPI 一致性分析。

### ③ 值得做(真实缺口)

- **高价值低成本**: 进度基准线客观风险(`lib/okr/risk.ts`)· dashboard 增强三率/漏斗/分布(实测 dashboard 无此)· 复盘社交 Feed(`visibility.ts` 是读权限,非复盘可见性,需新做)· 首页 AI 风险驾驶舱
- **高价值中高成本(阶段2地基)**: 项目承接层 · 工作法(`Initiative.horizon`)· 容量/人力排期 · 企业指标库
- **补齐**: 管理规定配置中台(周期 `defaultCycles()` 写死)· 总结节奏 · 绩效仪表盘视角 · 面谈模板闭环

### ④ 需要重构(动新功能前的技术债)

- **🔴 重构-1 进度计算口径分裂(最优先)**: 至少 8 处各自重算进度(`store/okr.ts`、`dashboard/page.tsx`、`alignment-tree.tsx`、`scoring.ts`、`insights/derive.ts`、`services/okr-calibration.ts`、`okr-retrospective.tsx`、`okr-scoring.tsx`)。必须先抽 `lib/okr/progress.ts` SSOT。**这是做基准线风险的前置**,否则风险算法变成第 9 处分裂。
- **🔴 重构-2 任务模型割裂**: `Initiative`(OKR行动项,有 `linkedTaskId`)与 `Task`(`lib/store/chat.ts`)+ `app/tasks` 三套并行。做项目承接层/任务中心/甘特前须统一 work-item 模型。
- **🟡 重构-3 `lib/store/okr.ts` 815 行单文件**: 抽离计算层(并入重构-1)后 store 只留状态变更。

### 推荐执行序列(尊重依赖)

