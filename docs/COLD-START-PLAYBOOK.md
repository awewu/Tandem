# 上线冷启动运营方案 (Go-Live Cold Start Playbook)

> 版本：v1.0  日期：2026-06-25  
> 归属：PRD-v2 遗憾3补全 — P7 之后的前 90 天运营动作  
> 原则：代码上线是起点，不是终点；冷启动成败决定平台能否真正跑起来。

---

## 1. 冷启动的核心挑战

| 挑战 | 说明 |
|---|---|
| 数据库空库 | 产品目录、租户、客户、价格全部为零，任何功能演示都是白屏 |
| 经销商无动力 | 没有初始激励，经销商不会主动注册和录入数据 |
| C 端无流量 | 无 SEO 积累，无口碑，问诊入口无人知道 |
| 功能半成品 | M12/M14/M15 三个 MISS 模块尚未落地代码 |
| 运营流程未磨合 | 业务团队第一次用系统，流程摩擦点不明确 |

---

## 2. 前置条件（上线门禁，不达不开放）

- [ ] Crosswalk MISS 模块清零（M12 design↔Rysnova / M14 PIPL合规 / M15 事件总线）
- [ ] 产品目录至少完成 Rheem + Everhot 两个品牌的 L1/L2 分类和 20 个 SKU 录入
- [ ] 至少 2 个租户（经销商账号）完成端到端演练（注册→问诊→报价→订单）
- [ ] 等保二级备案或启动申请（如暂未完成需管理层签字豁免并记录）
- [ ] 数据备份策略验证（执行一次 restore 演练）

---

## 3. D0–D30：种子阶段（内部+邀请制）

**目标**：3–5 家种子经销商上线，数据库从零到有，找出第一批真实 Bug。

### 3.1 数据准备（D0 前完成）

| 任务 | 责任人 | 完成标志 |
|---|---|---|
| 导入 Rheem / Everhot / Ruud 产品目录（L1→L3，含图片、参数、基准价） | 产品经理 | 管理后台可检索 |
| 创建总部管理员账号，配置 RBAC 角色权限 | 研发 | 业务控制台可登录 |
| 创建 3–5 家种子经销商租户，预置联合品牌模板 | 运营 | 各租户登录后能看到自己品牌页 |
| 录入 2–3 个真实已成交案例作为演示项目 | 运营 | 客户门户可查看 |

### 3.2 种子经销商激活

- 一对一上门培训（1天），重点：问诊入口→报价→提交订单完整链路
- 给予**前 3 个月免费**权益（或返利政策），绑定 3 个月留存
- 每周 1 次在线答疑（30 min），问题记录进 issue tracker

### 3.3 D0–D30 核心指标

| 指标 | 目标值 |
|---|---|
| 活跃租户数 | ≥ 3 |
| 完整问诊→报价流转次数 | ≥ 10 |
| 致命 Bug (P0) | = 0（发现即修） |
| 功能可用率（前 5 个核心路径） | ≥ 90% |

---

## 4. D31–D60：扩散阶段（区域推广）

**目标**：10–20 家经销商，验证多租户隔离无数据泄漏，问诊 C 端开放公测。

### 4.1 经销商招募

- 利用种子经销商口碑介绍（裂变追踪 M08 开始采集 referral 数据）
- 集团销售团队随拜访演示：15 分钟演示套件（录制好的视频 + 可现场操作的演示账号）
- 激励：签约即赠「经销商数字名片页」（DAM 功能，M09）+ 1 年免费 Rysnova 基础版

### 4.2 C 端问诊公测

- 瑞诺瓦 AI 问诊入口接入微信/小红书/抖音 3 个流量渠道（最低成本：每平台发 5 条内容）
- 建立 UTM 追踪，问诊流量来源数据进 CRM（M10）
- 目标：前 30 天 C 端问诊 ≥ 100 次，转留资率 ≥ 20%

### 4.3 D31–D60 核心指标

| 指标 | 目标值 |
|---|---|
| 注册经销商 | ≥ 10 |
| C 端问诊次数 | ≥ 100 |
| 问诊→留资转化率 | ≥ 20% |
| 留资→经销商跟进率 | ≥ 80%（系统自动分配，跟进有记录） |

---

## 5. D61–D90：验证阶段（商业闭环）

**目标**：完成第一个从「问诊→报价→签单→施工→验收」的完整闭环案例，验证财务模块（M11）和施工交付链路。

### 5.1 必须完成的第一单

- 选择 1 个种子经销商的真实客户
- 全程走系统：AI 问诊 → 设计师工作台出方案 → 报价锁单 → Rysnova 出图 → 施工管理 → 客户门户验收
- 全程截图/录像，作为对外宣传素材和内部培训案例

### 5.2 运营分析与 V2 迭代清单

- 汇总 90 天用户反馈，按频次排序 Top 10 功能需求
- 将 MISS 模块（M12/M14/M15）修复状态纳入 V2 Sprint 计划
- Crosswalk 脚本在 D90 重跑一次，目标：MISS = 0，Partial ≤ 2

### 5.3 D61–D90 核心指标

| 指标 | 目标值 |
|---|---|
| 注册经销商 | ≥ 20 |
| 完整闭环案例 | ≥ 1 单（有收款记录） |
| 月活跃用户（MAU，含经销商+客户门户） | ≥ 50 |
| V2 需求清单确认 | 完成 Top 10 排序并指派负责人 |

---

## 6. 冷启动期风险与对策

| 风险 | 对策 |
|---|---|
| 经销商数据录入抵触 | 提供 Excel 模板，运营代劳导入初始数据 |
| C 端问诊无流量 | 种子经销商自带客户；不依赖自然流量 |
| MISS 模块阻塞业务 | M12 手工 workaround（设计稿 PDF 附 Rysnova 工单号）；M14 隐私政策静态页先上 |
| 财务闭环未打通 | D60 前报价单先走线下签字，系统仅留档记录 |
| 服务器单点故障 | D0 前完成一次切换演练；告警接入企业微信 |

---

## 7. 90 天结束后的交接

- Crosswalk 报告归档（`evidence/crosswalk/`）
- 冷启动期 Bug 清单归档（issue tracker → PRD V2 风险表补录）
- 运营数据导出存档（月报格式，送管理层）
- 进入 V2 正式迭代节奏（双周 Sprint）
