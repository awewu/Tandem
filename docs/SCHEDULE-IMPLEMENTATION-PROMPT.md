# 日程管理实现窗口话术

请基于项目中的需求文档 `docs/SCHEDULE-PRD.md` 实现“日程管理”功能。本次需求只以该文档为准，重点包括日程创建、周期性重复日程、参会人自动加入、邮件通知、通用提醒中心、系统内提醒、IM 提醒参会人、时间冲突标识、日程订阅与详情权限审批。

实现前请先阅读:

- `docs/SCHEDULE-PRD.md`
- 项目中已有的日程、通知、用户、邮箱、权限相关代码
- 现有数据库 schema / migration / API / UI 结构

请按项目现有架构做最小且一致的实现，不要重写无关模块。

## 必须实现的业务规则

1. 用户只能在今天及未来日期创建日程，过去日期前后端都要拦截。
2. 创建日程时支持填写标题、开始时间、结束时间、地点/会议方式、说明、提醒时间、参会人邮箱、重复规则。
3. 参会人邮箱选择框需要支持下拉、多选、模糊查询，同时允许输入外部邮箱。
4. 系统内参会人收到邀请后自动加入日程，不需要接受、拒绝或暂定。
5. 外部邮箱只接收创建、变更、取消邮件，不进入系统日程，不接收系统内提醒。
6. 创建、修改、取消日程时，需要给发起人和所有参会人发送对应邮件。
7. 第一版提醒只做系统内提醒，不做邮件提醒；日程提醒需要接入通用提醒中心，后续 OKR、审批、待办等提醒也可复用。
8. 发起人修改或取消日程时，系统内参会人的日程和提醒任务需要同步更新或取消。
9. 日程取消建议标记为已取消，不做物理删除。
10. 时间冲突不阻止创建，但需要在日程展示中显示“时间冲突”标识。
11. 创建日程时有“重复”开关，开启后支持周期性重复日程。
12. 重复日程第一版支持每天、每周、每月、工作日、自定义重复。
13. 修改重复日程时，需要支持“仅修改本次日程”“修改本次及以后日程”“修改整个重复日程”。
14. 取消重复日程时，需要支持“仅取消本次日程”“取消本次及以后日程”“取消整个重复日程”。
15. 用户之间可以订阅对方日程。
16. 订阅时可选择是否申请查看完整详情；未开启则默认只看忙闲，不需要对方审批。
17. 申请查看完整详情需要被订阅人同意；同意前只能看忙闲。
18. 被订阅人可以拒绝或撤销详情权限，订阅人降级为只能看忙闲。
19. 订阅人可以取消订阅，取消后不再看到对方日程。
20. 点击“IM 提醒参会人”后，需要弹出会议选择弹窗，用户选择自己的某个会议后，系统创建或复用 IM 群，并在群内发送参会提醒。
21. IM 群成员包含当前操作用户、会议发起人和系统内参会人，不包含外部邮箱参会人。
22. 提醒到期后不能只依赖日历页面轮询；需要有通用后台队列处理到期提醒，并写入消息中心。
23. 用户在线时，提醒到期需要有页面 toast 或明显提示；消息中心入口需要清晰可见，并显示未读角标。
24. 如果用户开启浏览器推送，提醒到期后需要尝试 Web Push 投递。
25. 后台队列和前端轮询可能同时触发处理，提醒任务领取必须先进入处理中状态，避免重复投递。
26. 前端轮询不仅处理当前用户到期提醒，还需要补拉最近产生的提醒通知，避免后台队列先处理后在线 toast 丢失。
27. 失败提醒第一版最多自动重试 3 次，超过后保持失败状态，便于后续增加管理页、重放或告警。

## 建议拆分任务

1. 梳理现有日程、通知、用户、邮箱相关代码与数据模型。
2. 设计或扩展日程数据模型，覆盖普通日程、重复系列、重复实例、参会人、外部邮箱、取消状态、提醒任务。
3. 设计或扩展订阅数据模型，覆盖订阅状态和详情权限状态。
4. 实现创建日程 API 与 UI，包括参会人邮箱多选、模糊查询、外部邮箱输入、重复规则配置。
5. 实现系统内参会人自动加入与外部邮箱只发邮件逻辑。
6. 实现日程修改、取消和重复日程范围选择。
7. 实现邮件通知模板: 日程通知、日程变更、日程取消。
8. 实现通用提醒任务模型、仓库、后台处理队列、消息中心投递、在线 toast 和 Web Push 投递衔接；处理时需具备 claim / retry / cancel 能力。
9. 将日程提醒接入通用提醒中心，实现创建、更新、取消和到期投递。
10. 实现“IM 提醒参会人”入口、会议选择弹窗、IM 建群或复用、群内提醒消息发送。
11. 实现时间冲突判断和“时间冲突”标识展示。
12. 实现日程订阅、详情申请、同意、拒绝、撤销、取消订阅。
13. 补充核心测试或验证脚本，至少覆盖创建、修改、取消、重复、外部邮箱、订阅权限、IM 提醒参会人、通用提醒投递、时间冲突。

## 交付要求

- 保持现有代码风格和目录结构。
- 优先复用现有用户、通知、邮件、权限能力。
- 不要引入大范围无关重构。
- 修改数据库时同步提供 migration 或项目当前约定的 schema 更新方式。
- 完成后请说明改动文件、关键业务流、测试结果和未覆盖风险。
