# 日程管理需求文档

> 版本: v0.1
> 日期: 2026-07-16
> 状态: 需求基线

## 1. 背景

为支持企业内部协作，需要在系统中增加类似企业微信日程的能力。用户可以创建今天及未来日期的日程，邀请系统内用户或外部邮箱参会；系统内参会人自动加入日程并收到系统内提醒；用户之间可以订阅彼此日程，并根据授权查看忙闲状态或完整详情。

## 2. 功能范围

本期包含:

- 日程创建与参会人邀请
- 周期性重复日程
- 日程修改、取消与同步
- 创建、变更、取消邮件通知
- 系统内提醒
- IM 提醒参会人
- 时间冲突标识
- 用户日程订阅与详情权限审批

本期不包含:

- 参会人接受、拒绝、暂定邀请
- 外部邮箱用户的系统内日程同步
- 邮件提醒
- 外部日历同步

## 3. 日程创建

用户可以点击今天或今天以后的日期创建日程。过去日期不可创建日程，前端应禁用过去日期创建入口，后端也需要校验。

创建日程字段:

| 字段 | 要求 |
| --- | --- |
| 日程标题 | 必填 |
| 开始时间 | 必填 |
| 结束时间 | 必填，需晚于开始时间 |
| 地点/会议方式 | 选填 |
| 日程说明 | 选填 |
| 提醒时间 | 选填或使用默认值 |
| 参会人邮箱 | 选填，支持多个 |
| 重复 | 默认关闭，可开启周期性重复 |

参会人邮箱选择要求:

- 支持下拉选择。
- 支持多选。
- 支持模糊搜索。
- 支持选择系统内用户邮箱。
- 支持输入外部邮箱。

创建成功后:

- 发起人自己的日程中生成该事件。
- 系统内参会人自动加入该日程。
- 外部邮箱参会人不生成系统内日程。
- 系统向发起人和所有参会人发送创建通知邮件。
- 系统内用户按照提醒时间生成系统内提醒任务。

## 4. 周期性重复日程

创建日程时提供“重复”开关。

默认状态:

```text
重复: 关闭
```

开启后，用户可以配置周期性重复规则。

第一版建议支持的重复类型:

- 每天重复
- 每周重复
- 每月重复
- 工作日重复
- 自定义重复

重复配置字段:

| 字段 | 说明 |
| --- | --- |
| 重复类型 | 每天 / 每周 / 每月 / 工作日 / 自定义 |
| 重复开始日期 | 默认使用当前日程开始日期 |
| 重复结束方式 | 永不结束 / 指定结束日期 / 重复指定次数 |
| 重复结束日期 | 选择“指定结束日期”时必填 |
| 重复次数 | 选择“重复指定次数”时必填 |
| 每周重复日 | 每周重复或自定义按周重复时使用，可选择周一至周日 |

每月重复第一版按日期重复，例如“每月 15 日重复”。暂不强制支持“每月第二个周三”这类复杂规则。

重复日程创建规则:

- 用户创建重复日程后，系统根据重复规则生成多个日程实例。
- 每个实例都会出现在发起人日程中。
- 系统内参会人会自动加入每个重复实例。
- 外部邮箱只收到邮件通知，不生成系统内日程。
- 每个重复实例都参与时间冲突判断。
- 每个重复实例都根据提醒时间生成系统内提醒。

重复日程邮件规则:

- 创建重复日程成功后，建议只发送一封创建通知邮件。
- 邮件中展示重复规则，避免对每个实例单独发信造成打扰。

重复日程修改范围:

```text
仅修改本次日程
修改本次及以后日程
修改整个重复日程
```

修改规则:

- 仅修改本次日程: 只影响当前实例，其他重复实例不变。
- 修改本次及以后日程: 当前实例以及未来实例更新，当前实例之前的历史实例不变。
- 修改整个重复日程: 系列下所有未取消实例更新；第一版建议不修改已结束实例。

重复日程取消范围:

```text
仅取消本次日程
取消本次及以后日程
取消整个重复日程
```

取消后同步规则与普通日程一致。

## 5. 参会人规则

参会人收到邀请后，默认自动加入日程，不需要接受、拒绝或暂定。

系统内用户:

- 收到邮件通知。
- 自动加入系统日程。
- 收到系统内提醒。
- 日程变更或取消时自动同步。

外部邮箱:

- 收到邮件通知。
- 不加入系统日程。
- 不收到系统内提醒。
- 日程变更或取消时继续收到邮件通知。

如果外部邮箱后续注册为系统用户，本期暂不补充历史日程。

## 6. 日程修改

只有日程发起人可以修改日程。

可修改内容:

- 标题
- 开始时间
- 结束时间
- 地点/会议方式
- 日程说明
- 提醒时间
- 参会人
- 重复规则，适用于重复日程

修改成功后:

- 发起人自己的日程更新。
- 系统内参会人的日程自动同步更新。
- 新增的系统内参会人自动加入日程。
- 移除的系统内参会人从该日程中移除或标记为不再参与。
- 外部邮箱参会人只通过邮件接收变更通知。
- 系统发送日程变更邮件给发起人和相关参会人。
- 如果开始时间或提醒时间变化，系统内提醒任务同步重算。

## 7. 日程取消

只有日程发起人可以取消日程。

取消成功后:

- 发起人日程标记为已取消。
- 系统内参会人的日程同步标记为已取消。
- 未触发的系统内提醒任务取消。
- 已触发的提醒保留历史，不需要回撤。
- 系统发送日程取消邮件给发起人和所有参会人。

取消日程建议采用“标记取消”，不做物理删除，方便保留历史记录和排查通知问题。

## 8. 邮件通知

创建、修改、取消日程时均发送邮件。

邮件接收人:

- 发起人邮箱
- 系统内参会人邮箱
- 外部参会人邮箱

创建邮件格式:

```text
主题: 【日程通知】{日程标题}

你有一个新的日程安排。

日程标题: {日程标题}
发起人: {发起人姓名/邮箱}
开始时间: {开始时间}
结束时间: {结束时间}
地点/会议方式: {地点/会议方式}
提醒时间: {提醒时间}
重复规则: {重复规则，非重复日程可不展示}
参会人: {参会人邮箱列表}

日程说明:
{日程说明}

该日程已自动加入系统内参会人的日程，无需确认。
请按时参加。
```

变更邮件格式:

```text
主题: 【日程变更】{日程标题}

以下日程发生变更。

日程标题: {日程标题}
发起人: {发起人姓名/邮箱}
开始时间: {开始时间}
结束时间: {结束时间}
地点/会议方式: {地点/会议方式}
提醒时间: {提醒时间}
重复规则: {重复规则，非重复日程可不展示}
参会人: {参会人邮箱列表}

日程说明:
{日程说明}

请以最新日程信息为准。
```

取消邮件格式:

```text
主题: 【日程取消】{日程标题}

以下日程已取消。

日程标题: {日程标题}
发起人: {发起人姓名/邮箱}
原开始时间: {开始时间}
原结束时间: {结束时间}
地点/会议方式: {地点/会议方式}
重复规则: {重复规则，非重复日程可不展示}

该日程已取消，请知悉。
```

## 9. 通用提醒中心与系统内提醒

日程提醒接入通用提醒中心。提醒中心不是日程私有能力，后续 OKR 到期、审批超时、待办截止等提醒也应复用同一套提醒任务、后台队列和投递通道。

第一版只做系统内提醒，不做日程提醒邮件。

提醒对象:

- 发起人
- 系统内参会人

外部邮箱不接收系统内提醒。

提醒规则:

- 创建日程后，根据提醒时间生成通用提醒任务，`sourceType=calendar_event`，`sourceId=日程 ID`。
- 修改日程时间、参会人或提醒时间后，未触发提醒任务需要重算。
- 取消日程后，未触发提醒任务取消。
- 已触发提醒保留历史。
- 通用提醒任务需要支持去重 key，避免同一业务对象重复投递。
- 通用提醒任务需要支持状态流转: 待处理、处理中、已发送、失败、已取消。
- 通用提醒任务需要支持失败记录和后续重试扩展；第一版失败任务最多自动重试 3 次，超过后保留为失败状态供后续运维处理。

投递规则:

- 后台队列定时扫描到期提醒，不依赖用户停留在日历页面；队列领取提醒任务时需要先进入处理中状态，避免多个触发源重复投递。
- 用户在线时，到期提醒需要在页面内弹出 toast 或明显提示；即使后台队列先处理，前端轮询也需要从消息中心补拉最近提醒，避免在线提示丢失。
- 提醒需要写入消息中心，作为历史记录和未读来源；消息中心路径为 `/notifications`。
- 如果用户开启浏览器推送，提醒需要尝试发送 Web Push。
- 提醒入口需要在主导航或明显位置可见，并显示未读角标。

通用提醒中心扩展示例:

- OKR / KR 到期前 N 天提醒负责人。
- 审批超过 SLA 未处理时提醒审批人。
- 待办截止前提醒执行人。
- 未来可扩展 IM、企业微信、邮件等投递通道。

## 10. IM 提醒参会人

日历侧边栏提供“IM 提醒参会人”入口。该入口用于把某个会议的参会人拉入 IM 群，并在群内发送参会提醒。

交互流程:

1. 用户点击“IM 提醒参会人”。
2. 系统弹出会议选择弹窗。
3. 用户在弹窗中选择“我自己的某个会议”。
4. 用户确认后，系统基于该会议的系统内参会人创建 IM 群。
5. IM 群创建成功后，系统自动发送参会提醒消息。

会议选择范围:

- 只展示当前用户自己的会议。
- “自己的会议”包含当前用户发起的会议，以及当前用户作为系统内参会人参与的会议。
- 已取消会议不展示。
- 外部邮箱参会人不进入 IM 群，因为其不是系统内用户。

弹窗展示字段建议:

- 日程标题
- 开始时间
- 结束时间
- 地点/会议方式
- 参会人数
- 时间冲突标识，如有

建群规则:

- 群成员至少包含当前操作用户和会议的系统内参会人。
- 如会议发起人不是当前操作用户，也应加入群成员。
- 外部邮箱参会人不加入群。
- 如果同一会议已经存在对应 IM 群，建议复用已有群，避免重复建群。
- 如果同一会议没有对应 IM 群，则创建新群。

群消息格式:

```text
【会议提醒】{日程标题}

开始时间: {开始时间}
结束时间: {结束时间}
地点/会议方式: {地点/会议方式}

请相关参会人准时参加。
```

异常规则:

- 如果会议没有系统内参会人，提示“该会议暂无可提醒的系统内参会人”。
- 如果建群失败，提示“IM 群创建失败，请稍后重试”。
- 如果消息发送失败，保留已创建的群，并提示“群已创建，提醒消息发送失败”。

## 11. 时间冲突

日程时间冲突不阻止创建。

当某个用户在同一时间段存在多个日程时，日程仍然全部展示，并增加标识:

```text
时间冲突
```

冲突判断规则:

```text
事件 A: 10:00 - 11:00
事件 B: 10:30 - 11:30
结果: 冲突

事件 A: 10:00 - 11:00
事件 B: 11:00 - 12:00
结果: 不冲突
```

时间冲突标识适用于:

- 自己创建的日程
- 被邀请后自动加入的日程
- 订阅他人日程时看到的忙闲或详情
- 周期性重复日程生成的每个实例

## 12. 日程订阅

用户之间可以相互订阅日程。

订阅时需要选择是否申请查看完整详情。

订阅状态:

```text
已订阅
已取消
```

详情权限状态:

```text
未申请
待同意
已同意
已拒绝
已撤销
```

订阅规则:

- 用户 A 订阅用户 B，未开启“查看完整详情”时，订阅状态为“已订阅”，详情权限状态为“未申请”，A 可以直接查看 B 的忙闲状态，不需要 B 审批。
- 用户 A 订阅用户 B，开启“查看完整详情”时，订阅状态为“已订阅”，详情权限状态为“待同意”，B 收到详情查看申请；B 同意前，A 只能看到 B 的忙闲状态。
- B 同意申请后，详情权限状态变为“已同意”，A 可以查看 B 的完整日程详情。
- B 拒绝申请后，详情权限状态变为“已拒绝”，A 仍只能查看 B 的忙闲状态。
- B 撤销授权后，详情权限状态变为“已撤销”，订阅关系保留，A 降级为只能查看 B 的忙闲状态。
- A 取消订阅后，订阅状态变为“已取消”，A 不再查看 B 的日程。

## 13. 忙闲与详情展示

忙闲状态展示内容:

- 时间段
- 忙碌/空闲状态
- 时间冲突标识，如有

忙闲状态不展示:

- 标题
- 地点
- 说明
- 参会人
- 发起人

完整详情展示内容:

- 日程标题
- 开始时间
- 结束时间
- 地点/会议方式
- 日程说明
- 参会人
- 发起人
- 提醒时间
- 重复规则，如有
- 时间冲突标识，如有

## 14. 权限规则

- 发起人可以创建、修改、取消自己发起的日程。
- 参会人自动加入日程，但不能修改发起人的日程。
- 参会人可以查看自己参与的完整日程信息。
- 订阅者默认只能查看被订阅人的忙闲状态。
- 订阅者只有在详情权限为“已同意”时，才能查看被订阅人的完整日程详情。
- 被订阅人可以随时撤销详情查看权限。

## 15. 验收标准

- 用户不能在过去日期创建日程。
- 用户可以在今天或未来日期创建日程。
- 参会人邮箱支持下拉、多选、模糊查询。
- 支持输入外部邮箱。
- 创建成功后，系统内参会人自动加入日程。
- 外部邮箱不生成系统内日程。
- 创建成功后，发起人和参会人均收到邮件。
- 创建日程时可以开启重复，并配置周期性重复规则。
- 重复日程实例会进入发起人和系统内参会人的日程。
- 修改重复日程时，可以选择“仅本次”“本次及以后”“整个重复日程”。
- 取消重复日程时，可以选择“仅本次”“本次及以后”“整个重复日程”。
- 发起人修改日程后，系统内参会人日程自动同步。
- 发起人取消日程后，系统内参会人日程同步取消。
- 修改和取消日程时，相关人员收到对应邮件。
- 系统内用户能按提醒时间收到系统内提醒。
- 日程提醒到期后，不依赖用户停留在日历页面，后台队列会处理到期提醒。
- 用户在线时，到期提醒会弹出页面提示，并写入消息中心。
- 消息中心入口清晰可见，并显示未读角标。
- 开启浏览器推送后，日程提醒会尝试发送 Web Push。
- 外部邮箱不收到系统内提醒。
- 用户点击“IM 提醒参会人”后，会弹出会议选择弹窗。
- 用户可以在弹窗中选择自己的会议。
- 用户确认后，系统为该会议创建或复用 IM 群。
- IM 群成员包含当前操作用户、会议发起人和系统内参会人，不包含外部邮箱参会人。
- IM 群创建成功后，系统在群内发送参会提醒消息。
- 时间重叠的日程可以同时存在，并显示“时间冲突”。
- 用户可以订阅他人日程并查看忙闲状态。
- 申请查看完整详情需要被订阅人同意。
- 被订阅人同意后，订阅人可以查看完整详情。
- 被订阅人拒绝或撤销后，订阅人只能查看忙闲状态。
- 订阅人取消订阅后，不再看到对方日程。
