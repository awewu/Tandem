## 错误 #2: 户型模板加载后3D不工作

**错误类型**: P1 - 功能性错误
**错误描述**: 加载户型模板后，`parsedData` 变量未更新，导致3D预览失败

- 确保数据状态同步

**预防措施**:
- 明确区分全局状态和局部变量
- 添加数据流注释说明
- 建立状态变更检查点

**学习要点**:
- 数据流必须在关键节点显式同步
- 模板加载不仅是UI更新，还需要状态更新

## 错误 #3: 桌面端窗口不显示
**时间**: 2026-04-10 ~17:47, ~18:13
**错误类型**: P1 - 功能性错误
**错误描述**: Electron进程启动但窗口未显示或隐藏到后台
**根本原因**: 
- 窗口可能被最小化到系统托盘
- `show: false` 配置导致窗口初始隐藏
- 没有强制窗口显示到前台的逻辑

**修复方案**: 
- 添加 `mainWindow.show()` 强制显示
- 使用 Win32 API `SetForegroundWindow` 将窗口置顶
- 修复 `show: false` 配置为 `show: true`

**预防措施**:
- 桌面端启动必须验证窗口可见性
- 添加窗口状态恢复机制
- 提供备用浏览器访问方案

**学习要点**:
- Electron窗口管理需要显式控制
- 进程存在 ≠ 窗口可见
- 必须考虑窗口被隐藏到托盘的情况

## 错误 #4: 服务器单例模式构造函数错误
**时间**: 2026-04-10 ~17:52
**错误类型**: P0 - 阻塞性错误
**错误描述**: `TypeError: TemplateEngine is not a constructor`
**根本原因**: 
- 模块导出的是单例实例而非类
- 使用 `new` 关键字实例化单例导致错误
- 对模块导出方式理解不清

**修复方案**: 
- 将 `new TemplateEngine()` 改为直接使用导出的实例
- 检查模块导出方式：`module.exports = new TemplateEngine()` vs `module.exports = TemplateEngine`

**预防措施**:
- 使用模块前必须查看其导出方式
- 区分单例模式和类构造模式
- 添加模块使用注释

**学习要点**:
- Node.js 模块导出方式决定使用方式
- 单例模式：直接 require 使用
- 类模式：需要 new 构造实例

## 错误 #5: WebSocket 端口冲突
**时间**: 2026-04-10 ~17:53
**错误类型**: P1 - 功能性错误
**错误描述**: `Error: listen EADDRINUSE: address already in use :::3001`
**根本原因**: 
- HTTP服务器和 WebSocket 服务器使用相同端口
- 端口配置未分离

**修复方案**: 
- 将 WebSocket 服务器端口改为 3002
- 明确分离 HTTP (3001) 和 WebSocket (3002) 端口

**预防措施**:
- 每个服务必须有独立端口配置
- 添加端口冲突检测和自动切换
- 文档化端口分配策略

**学习要点**:
- HTTP 和 WebSocket 是不同的协议，需要不同端口
- 端口冲突是常见部署问题
- 需要灵活的端口配置机制

## 错误 #6: PowerShell 命令语法错误
**时间**: 2026-04-10 ~18:00
**错误类型**: P2 - 体验性问题
**错误描述**: `标记"&&"不是此版本中的有效语句分隔符`
**根本原因**: 
- 混淆了 Bash 和 PowerShell 语法
- PowerShell 不支持 `&&` 和 `&` 作为命令分隔符

**修复方案**: 
- 使用 PowerShell 语法：`;` 作为分隔符
- 或使用 `-ErrorAction` 参数

**预防措施**:
- 明确区分 Shell 类型 (Bash vs PowerShell vs CMD)
- 针对目标 Shell 编写兼容命令
- 测试命令在目标环境中执行

**学习要点**:
- Windows PowerShell 和 Bash 语法差异大
- 跨平台命令需要适配不同 Shell
- 使用 PowerShell 原生语法而非 Bash 语法
